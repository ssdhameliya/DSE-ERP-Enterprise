# Release Specification: DSE Web Admin Studio v10.0.38.06
**Desktop Baseline Revision**: `10.0.38`  
**Web Release Version**: `10.0.38.06` (Web Build #6)  
**Release Tag**: `web-v10.0.38.06`  
**Release Date**: 2026-10-21  
**Target Environment**: Production / Enterprise  

---

## 1. Executive Summary & Problem Analysis
Following the release of `v10.0.38.05`, user testing with comprehensive audit document `KPILIGHTMODEISSUE.docx` (34 screenshots) identified lingering Light Theme defects across multiple screens, sub-screens, modals, settings panels, buttons, and form controls:

1. **KPI Cards Proportional Stretching (Right-Side Void Elimination)**:
   - *Defect*: KPI ribbons on multiple registers (Sales Returns, Credit Notes, Quotations, Purchase Returns, Debit Notes, Items Master, Barcode Studio, General Ledger, Stock Register, Reports) failed to fill the container width, stopping at ~70-80% and leaving an unsightly empty white void on the right.
   - *Root Cause*: Cards were bounded by an artificial `max-width: 240px`/`280px` or `.kpi-grid` containers lacked `width: 100% !important; flex: 1 1 0 !important; max-width: none !important;`.
   - *Fix*: Remove `max-width` restrictions on all KPI cards in single-row ribbons so cards expand evenly and proportionally across 100% of the available horizontal space.

2. **Dark Slate KPI Cards in Light Mode**:
   - *Defect*: KPI cards on Items Master, Barcode Studio, General Ledger, Data Import Studio, Stock Register, Executive Reports Dashboard, and Scheduled Reports appeared in dark slate (`#1e293b` / `#334155`) with low-contrast, unreadable text.
   - *Root Cause*: Hardcoded inline backgrounds (`rgba(30,41,59,0.5)`, `#1e293b`, `rgba(15,23,42,...)`) or module-specific card classes that bypassed theme rules.
   - *Fix*: Apply universal light theme card overrides (`background: #ffffff !important; border: 1px solid #cbd5e1 !important; color: #0f172a !important;`) and clean up hardcoded inline card backgrounds across all views in `index.html`.

3. **Manual Match Modal KPI Wrap Bug**:
   - *Defect*: In the Match Transaction modal (`#modal-manual-match`), the 6th metric card ("Settlement Status") dropped onto a second row, and the transaction info box displayed dark slate with unreadable text.
   - *Root Cause*: Modal KPI grid lacked `flex-wrap: nowrap !important;` and the header metadata box had inline `background: rgba(0,0,0,0.25)`.
   - *Fix*: Enforce single-row flex nowrap with dense card scaling, and convert the metadata info box to a light `#f8fafc` container with `#0f172a` text.

4. **Master Data "Lookup Categories" Left Rail Width**:
   - *Defect*: The Lookup Categories rail on `#view-masters` was too narrow after previous compression.
   - *User Instruction*: "Just increase ( 50% if current panel ) for look up categories".
   - *Fix*: Increase panel width by 50% from `230px` to `345px` (`min-width: 320px; max-width: 360px;`).

5. **Delete Button Dead / Unresponsive in Item Master & Registers**:
   - *Defect*: "Delete Item" button in Item Master toolbar did nothing when clicked.
   - *Root Cause*: Missing or mismatched click handler in `ItemMasterController.js` / `index.html`, or disabled attribute not reacting to row selection.
   - *Fix*: Implement robust single and multi-item delete confirmation dialog using `AppDialogService.confirm` in `ItemMasterController.js`.

6. **GSTR-1 Statutory Return Center & Dead Table Buttons**:
   - *Defect*: All buttons under GSTR-1 Statutory Return Center (`Table 4: B2B Invoices`, `Table 7: B2C Small`, `Table 9B: CDNR`, `Table 12: HSN Summary`, `Table 13: Documents Issued`) were unresponsive.
   - *User Instruction*: "All Button under GSTR-1 satutory Return center is dead and nothing happened also can e changed button like how we have in reporting dashboard 3 button name statrt with GSTR".
   - *Fix*: Wire active table view switching in `GstController.js`, update button styling with attractive gradient pills matching Reports Dashboard.

7. **Saved Reports Catalog Action Button Dead**:
   - *Defect*: Clicking `::: Actions ▼` on rows in the Saved Reports Catalog did not open the action dropdown.
   - *Root Cause*: Scope issue or missing click binding in `ReportsController.js` `renderSavedReportsList`.
   - *Fix*: Fix event delegation and dropdown positioning for Saved Reports action menus.

8. **Modals with Dark Navy Bodies in Light Mode**:
   - *Defect*: Modal bodies in Edit Supplier (`#modal-party`), Edit Item (`#modal-item`), Add Customer, Add Supplier, and Audit Event (`#modal-audit`) rendered pitch black (`#0f172a`) in Light Mode.
   - *Root Cause*: Hardcoded inline styles `background: #0f172a` on `.modal-body` or modal dialog containers.
   - *Fix*: Remove dark inline backgrounds and enforce `#ffffff !important; color: #0f172a !important;` across all modal dialogs.

9. **Settings Panels with Dark Slate Backgrounds**:
   - *Defect*: Settings sub-panels across Company & Billing (Application Branding), Payment & Bank (Reconciliation, QR Code), Invoice & Delivery (Signature), Email Delivery (SMTP, Templates), and Security & Session (Inactivity bar) displayed dark slate blocks.
   - *Fix*: Overhaul settings container styles in Light Mode to clean `#ffffff` cards with `#cbd5e1` borders and `#0f172a` text.

10. **Settings Checkboxes & Switch Text Invisible (White on White)**:
    - *Defect*: Checkbox pill labels in Notifications and Module Management had white text against white cards, rendering all options invisible.
    - *Fix*: Force `color: #0f172a !important; font-weight: 600 !important;` on all checkbox labels, toggle pills, and switch text in `body.light-theme`.

11. **User Access Role Matrix Footer Bar & Permission Matrix Header**:
    - *Defect*: Bottom "Save Permissions" sticky toolbar and Permission Matrix header rendered in pitch black `#1e293b`.
    - *Fix*: Style toolbar to `#ffffff` / `#f8fafc` with subtle top border and high-contrast button styling.

12. **Generic Light Mode Input Focus "Blank" (Black) Flash Glitch**:
    - *Defect*: When clicking on any dropdown, text field, textarea, search bar, or date picker, the control briefly flashes pitch black before transitioning to white.
    - *Root Cause*: Global rule `.erp-input-active-focused, input:focus, select:focus, textarea:focus` enforced `background: rgba(15, 23, 42, 0.95) !important;` with a CSS transition, applying a dark background on focus before the light theme rule could take effect.
    - *Fix*: Scope all dark `:focus` background rules strictly to `body:not(.light-theme)`, and lock Light Theme form controls to zero background transition (`transition: border-color 0.1s ease, box-shadow 0.1s ease !important;`).
