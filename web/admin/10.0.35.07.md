## 3. Deep-Dive Root Cause Analysis

### Defect 1: Sale Import - Desktop Silent 0-Records & Web False Insufficient Stock
- **Desktop Investigation**: In [ImportService.java:405-412](file:///c:/Users/JATIN%20DHAMELIYA/Downloads/DSE-ERP-10.0.25-INTELLIJ-READY-FINAL-V19/DSE-ERP-10.0.25/desktop/src/main/java/org/example/service/ImportService.java#L405-L412), if an invoice already exists in the system, it is marked `SKIPPED`. In [ImportService.java:89-94](file:///c:/Users/JATIN%20DHAMELIYA/Downloads/DSE-ERP-10.0.25-INTELLIJ-READY-FINAL-V19/DSE-ERP-10.0.25/desktop/src/main/java/org/example/service/ImportService.java#L89-L94), `failedCount()` only counts rows where `status == "FAILED"`. When all rows are skipped, `failedCount() == 0`. In [ImportController.java:1329](file:///c:/Users/JATIN%20DHAMELIYA/Downloads/DSE-ERP-10.0.25-INTELLIJ-READY-FINAL-V19/DSE-ERP-10.0.25/desktop/src/main/java/org/example/controller/ImportController.java#L1329), `if (!dryRun && result.failedCount() == 0)` fired `showCompletedState(result)` which displayed "Import completed successfully" despite 0 records created.
- **Web Investigation**: In [ImportService.js:550-554](file:///d:/ERP%20Website/admin/js/services/ImportService.js#L550-L554), the cache was populated as `availableStockByItem.set(code, it.availableStock || 0)`. On the server, `ItemDto` defines `openingStock`, NOT `availableStock`. Thus `it.availableStock` was always `undefined`, setting available stock to 0 and triggering `"Insufficient stock for item ITEM-0001 (required X, available 0)"` during preflight.

### Defect 2 & 4: Purchase Import Preflight Parity & ERP Server Error Transparency
- **Preflight Discrepancy**: Desktop validates item codes against the configured reference pattern (`REF_ITEM`, e.g. `ITMXXX`) via `ImportDocumentPolicy.requireReference(referenceFormats, "REF_ITEM", item, null, "Item Code")`. Web only validated invoice numbers (`REF_PURCHASE`). Web allowed invalid item codes (like `ITEM-0001`) to pass preflight.
- **Backend Masking**: When Web called `/api/operations/purchases`, the backend failed with `IllegalArgumentException: Item not found: ITEM-0001`. In [ApiExceptionHandler.java:81-89](file:///c:/Users/JATIN%20DHAMELIYA/Downloads/DSE-ERP-10.0.25-INTELLIJ-READY-FINAL-V19/DSE-ERP-10.0.25/server/src/main/java/org/example/server/web/ApiExceptionHandler.java#L81-L89), any unhandled `Exception.class` returned the hardcoded string: `"The ERP server could not complete this operation. Check the server log for the underlying error."`, obscuring the actual cause from the user.

### Defect 3: Bank Statement Import Failure on Web
- In [ImportService.js:1554](file:///d:/ERP%20Website/admin/js/services/ImportService.js#L1554), date parsing used raw substrings without ISO conversion:
  `const dateStr = (getVal(r, 'transaction_date') || '').substring(0, 10);`
  When users uploaded statements with dates in `DD-MM-YYYY` format (Kotak standard), `dateStr` remained `19-10-2026`. When passed to `/api/bank-statements/imports`, backend `date(row.transactionDate())` or PostgreSQL column storage threw an exception, masked by the generic error.

### Defect 5: PDF Generation vs. Browser Print Popup
- 20+ instances across `ReportsController.js`, `PurchaseController.js`, `FinanceController.js`, and `SalesController.js` called `window.print()` / `win.print()`. This forces the browser to open the system print dialog.
- For canonical documents (Sales Invoices, Purchase Orders), the backend provides `/api/documents/render?type={type}&number={number}&format=PDF` which streams authoritative PDF bytes.
- For tabular registers and reports, client-side PDF generation or direct blob file downloads must be triggered via `<a download="filename.pdf">`.

### Defect 6: Customer 360° & Supplier 360° Tabs & Attachment Auth Error
- **Tabs**: In `index.html:7800-7815`, tabs used `.sub-tab-btn` without the segmented pill container or active cyan styling used in Reporting Dashboard.
- **Attachment 401 & 404**: In [PartyController.js:1692-1697](file:///d:/ERP%20Website/admin/js/controllers/PartyController.js#L1692-L1697), the upload handler called `localStorage.getItem('token')` (which is null, since the system stores tokens under `'dse_access_token'`). Furthermore, the URL was `/api/attachments/document/...` which does not exist on the server.
- The server endpoints in [SupportController.java:9-12](file:///c:/Users/JATIN%20DHAMELIYA/Downloads/DSE-ERP-10.0.25-INTELLIJ-READY-FINAL-V19/DSE-ERP-10.0.25/server/src/main/java/org/example/server/support/SupportController.java#L9-L12) are:
  - `GET /api/support/documents/{type}/{id}/attachments`
  - `POST /api/support/documents/{type}/{id}/attachments?filename={name}` (binary payload)
  - `GET /api/support/documents/{type}/{id}/attachments/{attachmentId}` (download/preview)
  - `DELETE /api/support/documents/{type}/{id}/attachments/{attachmentId}`

### Defect 7: Purchase Recon Register Desktop Discrepancies
- **System Ref**: In [PurchaseReconController.js:122](file:///d:/ERP%20Website/admin/js/controllers/PurchaseReconController.js#L122), code read `r.systemRef || 'PRC-' + r.id`. The server `ReconDto` field is `r.reference`.
- **Invoice Date**: In [PurchaseReconController.js:25-34](file:///d:/ERP%20Website/admin/js/controllers/PurchaseReconController.js#L25-L34), `formatDate()` hardcoded `DD/MM/YYYY` instead of calling `window.FormatUtil.formatDate()`.
- **Linked Ref**: Field `r.linkedRef` does not exist in `ReconDto`. `ReconDto` provides `List<BankLinkDto> bankLinks`.
- **Recon Supplier KPI**: In [PurchaseReconController.js:512, 551](file:///d:/ERP%20Website/admin/js/controllers/PurchaseReconController.js#L512), code read `s.reconRecordsCount`. The server `SupplierDto` field is `s.reconCount`.
- **Action Button**: In line 558, the button was styled `btn-secondary` instead of `btn-purple`.

### Defect 8: Bank Statement History & Linked Record Highlighting
- **History Actions**: In [BankStatementController.js:1624](file:///d:/ERP%20Website/admin/js/controllers/BankStatementController.js#L1624), batch items had separate `Open` and `Delete` buttons instead of the standard purple `Actions ▼` dropdown menu.
- **Linked Highlighting**: In lines 2123-2143, when navigating to Bank Entry or Expense Entry, the code searched for element `fe-search` (which does not exist; the actual IDs are `bank-search` and `exp-search`), invoked `applyFilters()` (the actual method is `applyFinanceFilters()`), and omitted `highlightRowInTable`.

### Defect 9: Bank Entry Table Alignment & Operating Expense Dropdown
- **Header/Body Alignment**: In `index.html:4490`, `<th id="th-bank-mode" style="display: none;">Mode</th>` was hidden, leaving 8 `<th>` elements. `renderBankTable` rendered 9 `<td>` cells per row, offsetting all columns to the left.
- **Operating Expense Dropdown**: In [FinanceController.js:664](file:///d:/ERP%20Website/admin/js/controllers/FinanceController.js#L664), code queried `EXPENSE_HEAD`. In PostgreSQL and `MasterDataController.java`, the category code is `EXPENSE_CATEGORY`. The server returned an empty array, so `catEl.innerHTML` was never updated from `<option value="">Loading categories...</option>`.

### Defect 10: Stock Register KPI Cards & Universal Height Parity
- Stock Register KPI cards in `index.html:7192-7232` lacked `.standard-kpi-icon` and `.standard-kpi-body` elements.
- Enforce uniform height: `.standard-kpi-card` with `min-height: 82px; height: 84px;` matching Reporting - Active Sales.

## 4. Technical Implementation Plan

### Phase 1: Desktop ERP & Server Hardening
1. **`ImportService.java` & `ImportController.java`**:
   - Update `ImportResult` to track `skippedCount`.
   - In `ImportController.java:1658-1664`, if `result.imported == 0 && result.skipped > 0`, set status to `"Import completed — no new records created (all existing records protected)"` with warning styling.
2. **`ApiExceptionHandler.java`**:
   - Replace generic string fallback with root-cause extractor:
     ```java
     Throwable root = error.getCause() != null ? error.getCause() : error;
     String msg = root.getMessage() != null && !root.getMessage().isBlank() ? root.getMessage() : error.getMessage();
     ```
   - Add specialized exception handlers for `DataIntegrityViolationException` and `SQLException` to return user-friendly messages for duplicates and foreign key violations.

### Phase 2: Web Data Import Studio (`ImportService.js`)
1. **Sale Import Stock Fallback**:
   - Update line 553 to compute stock: `(it.availableStock !== undefined && it.availableStock !== null) ? Number(it.availableStock) : Math.max(0, Number(it.openingStock || 0))`.
2. **Purchase Preflight Reference Parity**:
   - Validate Item Code against `refFormats['REF_ITEM']` (e.g. `ITMXXX`) and Supplier Code against `refFormats['REF_SUPPLIER']`. Flag non-matching rows as `FAILED` during preflight, matching Desktop behavior.
3. **Bank Statement Date Normalization**:
   - Parse `transaction_date` into ISO `YYYY-MM-DD` and `transactionTimestamp` into `YYYY-MM-DDTHH:mm:ss`.

### Phase 3: Universal PDF Generation
1. In `ApiService.js`, provide `downloadDocumentPdf(type, number)` that fetches `/api/documents/render?type=...&number=...&format=PDF` and triggers a real file download.
2. Replace all `window.print()` / `win.print()` calls in `ReportsController.js`, `PurchaseController.js`, `FinanceController.js`, and `SalesController.js` with direct file downloads.

### Phase 4: Customer 360° & Supplier 360° Tabs & Attachments
1. **Tabs**: Replace `.sub-tab-btn` with `register-tab-strip` styling matching the Reporting Dashboard.
2. **Attachment Service**:
   - In `PartyController.js` and `ReportService.js`, route requests to `/api/support/documents/{type}/{id}/attachments`.
   - Use `localStorage.getItem('dse_access_token')`.
   - Implement `previewPartyDocument` using `window.ApiService.viewFile()`.
   - Implement `deletePartyDocument` calling `DELETE /api/support/documents/{type}/{id}/attachments/{metaId}`.

### Phase 5: Purchase Recon & Recon Supplier
1. Bind `r.reference` (fallback `'PRC-' + r.id`).
2. Format invoice date with `window.FormatUtil.formatDate()`.
3. Format Linked Ref from `r.bankLinks`. On click, navigate to target document and highlight row.
4. In Recon Supplier, bind `s.reconCount` for both table column and KPI card.
5. Set action button class to `btn-purple`.

### Phase 6: Bank Statement History & Row Highlighting
1. Update History drawer action buttons to the unified purple `Actions ▼` dropdown menu.
2. In `openLinkedDocument()`, target correct search input IDs (`bank-search`, `exp-search`), call `window.FinanceController.applyFinanceFilters()`, and invoke `highlightRowInTable()`.
3. Implement `window.FinanceController.openBankStatement(stmId)` to navigate to `view-bank-statement` and load workspace.

### Phase 7: Bank Entry Alignment & Expense Dropdown
1. Align Bank Entry table header: Make `<th id="th-bank-mode">` visible with matching width or harmonize header/body to 9 columns.
2. In `FinanceController.js`, query `EXPENSE_CATEGORY` for expense heads and await lookups on modal open.

### Phase 8: Stock Register KPI Cards & Global Height Standardization
1. Update Stock Register KPI cards in `index.html` to include icons (`📦`, `✅`, `⚠️`, `❌`, `💰`) and `.standard-kpi-body` wrappers.
2. Apply uniform height (`min-height: 82px; height: 84px;`) across all registers.
