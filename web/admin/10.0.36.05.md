### Root Cause 1: Sales & Purchase Register Loader Fails in Web (500 Error) While Desktop Succeeds
In Desktop, importing `Sales_Template.xlsx` (`JI/25-2026/0161` & `0162`) succeeded completely (2 passed, 0 failed, visible in Sales Register with ₹ 3,935.00 and ₹ 2,360.00). In Web, importing `Sales_Template1.xlsx` passed pre-flight validation, but failed during execution with:
`• JI/25-2026/0163: The ERP server could not complete this operation. Check the server log for the underlying error.`
`• JI/25-2026/0164: The ERP server could not complete this operation. Check the server log for the underlying error.`

Deep comparison between Desktop `ImportService.java` and Web `ImportService.js` identified four major systemic contract mismatches:

1. **Additional Charges Completely Dropped in Web**:
   - In `Sales_Template.xlsx` and `Sales_Template1.xlsx`, rows specify additional charges:
     `charge_1_type`: `'Freight'`, `charge_1_amount`: `250`, `charge_1_taxable`: `true`, `charge_1_gst_percent`: `18`
     `charge_2_type`: `'Packing'`, `charge_2_amount`: `100`, `charge_2_taxable`: `false`, `charge_2_gst_percent`: `0`
   - **Desktop (`ImportService.java:862-881`)**: Parses `charge_1_...` and `charge_2_...` into `SalesCharge` objects and includes them in `document.setCharges(extras.charges())`. When calculating totals via `DocumentCalculationEngine.totals()`, Desktop adds taxable charges and calculates charge tax (Freight 250 + 18% GST = 295; Packing 100 non-taxable = 100; items 3000 + 18% GST = 3540; Grand Total = 3935.00).
   - **Web (`ImportService.js:1287` & `1414`)**: Hardcoded `charges: []`! The freight and packing charges were silently discarded, creating a financial calculation mismatch and causing charges to be dropped.
2. **Missing Database-Enforced NOT NULL Column (`sameAsBilling`)**:
   - In PostgreSQL `sales_header` (migration `V7_1_6__delivery_flag_and_notification_category.sql` line 13), `same_as_billing` is `BOOLEAN NOT NULL DEFAULT TRUE`.
   - In `SalesHeaderEntity.java:42`: `@Column(name="same_as_billing", nullable=false) private Boolean sameAsBilling = Boolean.TRUE;`.
   - In `BusinessOperationsService.java:683`: `h.setSameAsBilling(d.sameAsBilling());`.
   - **Desktop**: Explicitly sets `isSameAsBilling() = true` on `saleDto`.
   - **Web**: Completely omitted `sameAsBilling` in `salePayload`. When deserialized into Java record `SaleDto(..., boolean sameAsBilling, ...)`, Jackson defaults missing JSON booleans to `false`. When `sameAsBilling = false`, the server expects separate delivery address/GSTIN snapshots, but Web sent none.
3. **Missing Header Fields in Web `salePayload`**:
   - `dueDate`: Desktop calculates `invoiceDate.plusDays(termDays(terms))` (e.g. `2026-10-19 + 15 days = 2026-11-03`). Web left `dueDate` empty (`undefined`), leaving payment due tracking broken.
   - `billingAddress` & `deliveryAddress`: Desktop populates from customer master (`party.getAddress()`). Web omitted them.
   - `billingGstin` & `deliveryGstin` & `gstin`: Desktop populates from customer master (`party.getGstin()`). Web omitted them.
   - `quantity`: Desktop calculates the total quantity across lines. Web omitted it (defaulting to 0.0).
   - `documentStatus`: Web passed `'POSTED'`. In Desktop, imported transactions use canonical `'APPROVED'`.
4. **Purchase Import Contract Discrepancy**:
   - In Web `ImportService.js:1390-1418`:
     - Omitted `charges`, `sameAsBilling`, `dueDate`, `billingAddress`, `deliveryAddress`, `billingGstin`, `deliveryGstin`.
     - Omitted `warehouse` and `currency`.

### Root Cause 2: Generic Server Error Masking in `ApiExceptionHandler.java`
The user explicitly requested:
> *"i want to make sure that server error should be give user friend error messag e"*

In `D:\GitHub\DSE-ERP-Primary\server\src\main\java\org\example\server\web\ApiExceptionHandler.java`:
- Lines 81–89 catch the broad `Exception.class` and return:
```java
@ExceptionHandler(Exception.class)
public ResponseEntity<Map<String, Object>> serverError(Exception error) {
    error.printStackTrace();
    return ResponseEntity.status(HttpStatus.INTERNAL_SERVER_ERROR).body(Map.of(
        "status", HttpStatus.INTERNAL_SERVER_ERROR.value(),
        "code", "SERVER_ERROR",
        "message", "The ERP server could not complete this operation. Check the server log for the underlying error."
    ));
}
```
- When a database constraint error occurs (`DataIntegrityViolationException`), or a JSON deserialization error occurs (`HttpMessageNotReadableException`), or a bean validation error occurs (`ConstraintViolationException` / `MethodArgumentNotValidException`), `ApiExceptionHandler` throws away the real cause and masks it with the generic string *"The ERP server could not complete this operation. Check the server log for the underlying error."*.
- Neither the user nor the web UI could diagnose why the invoice failed.

## 3. Comprehensive Implementation Plan for Build `10.0.36.05`

### Phase 1: Server Exception Handling & User-Friendly Errors (`ApiExceptionHandler.java`)
1. In `D:\GitHub\DSE-ERP-Primary\server\src\main\java\org\example\server\web\ApiExceptionHandler.java` and staging copy `c:\Users\JATIN DHAMELIYA\Downloads\DSE-ERP-10.0.25-INTELLIJ-READY-FINAL-V19\DSE-ERP-10.0.25\server\src\main\java\org\example\server\web\ApiExceptionHandler.java`:
   - Add `@ExceptionHandler(DataIntegrityViolationException.class)`:
     - Extract `NestedExceptionUtils.getMostSpecificCause(error).getMessage()`.
     - Detect constraint types (Unique constraint, NOT NULL column constraint, Foreign Key constraint, Check constraint).
     - Return HTTP 409 Conflict with friendly message, e.g.:
       `"message": "Database constraint violation: " + friendlyConstraintExplanation`,
       `"details": specificCauseMessage`.
   - Add `@ExceptionHandler(HttpMessageNotReadableException.class)`:
     - Extract root JSON parsing/deserialization message.
     - Return HTTP 400 Bad Request with readable explanation (e.g. `"Invalid request format: " + specificMessage`).
   - Add `@ExceptionHandler(MethodArgumentNotValidException.class)` and `@ExceptionHandler(ConstraintViolationException.class)`:
     - Format field-level validation errors into a clean string.
   - Enhance `@ExceptionHandler(Exception.class)`:
     - Extract `Throwable root = NestedExceptionUtils.getMostSpecificCause(error)`.
     - If root message exists, return friendly error:
       `"message": root.getMessage()`,
       `"details": root.getClass().getSimpleName() + ": " + root.getMessage()`.
     - Never return an opaque, dead-end masked string.

### Phase 2: Web `ImportService.js` Sales & Purchases Full Desktop Parity
1. **Sales Import (`executeImport` -> `'Sales'` case)**:
   - Implement charge extraction helper `extractDocumentCharges(rows, getVal)`:
     - Extract `charge_1_type`, `charge_1_amount`, `charge_1_taxable`, `charge_1_gst_percent`.
     - Extract `charge_2_type`, `charge_2_amount`, `charge_2_taxable`, `charge_2_gst_percent`.
     - Validate amounts (>0), taxability (boolean), and GST percentages (0..100).
   - Replicate `DocumentCalculationEngine.totals()`:
     - Calculate `grossItems`, `discountAmount`, `itemTaxable`, `lineTax`.
     - Calculate `chargeAmount`, `taxableCharges`, `chargeTax`.
     - Calculate `subtotal = itemTaxable`, `gstAmount = lineTax + chargeTax`, `totalAmount = itemTaxable + lineTax + chargeAmount + chargeTax`.
   - Calculate `dueDate`:
     - Implement `parseTermDays(terms)` matching Desktop `ImportValueParser.termDays()` (extracts `\d+`, defaults to 0).
     - Compute `dueDate = invoiceDate + termDays` in `YYYY-MM-DD` format.
   - Populate Header Fields in `salePayload`:
     - `sameAsBilling: true` (mandatory NOT NULL).
     - `billingAddress: customerEntity.address || ''`.
     - `deliveryAddress: customerEntity.address || ''`.
     - `billingGstin: customerEntity.gstin || ''`.
     - `deliveryGstin: customerEntity.gstin || ''`.
     - `gstin: customerEntity.gstin || ''`.
     - `quantity: lines.reduce((acc, l) => acc + l.quantity, 0)`.
     - `documentStatus: 'APPROVED'`.
     - `charges: extractedCharges`.
2. **Purchase Import (`executeImport` -> `'Purchases'` case)**:
   - Extract charges from `charge_1_...`, `charge_2_...`, and optional `additional_charges` (Type|Amount|Taxable|GST).
   - Compute totals inclusive of charges.
   - Calculate `dueDate` based on `payment_terms`.
   - Populate `sameAsBilling: true`, `billingAddress`, `deliveryAddress`, `billingGstin`, `deliveryGstin`.
   - Populate `currency: 'INR'`, `warehouse: 'Default Warehouse'`, `documentStatus: 'APPROVED'`.
