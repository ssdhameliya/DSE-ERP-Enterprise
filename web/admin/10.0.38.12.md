## 1. Executive Summary & Architecture Strategy

Per `prinical.md` (Rules 1-17), `MANDATORY_DEVELOPMENT_PROTOCOL.md`, and the user's specific directive:
> **"i want to make served based 1st in desktop so once desktop build we nust need tocall the APi which is easy to fixed, right ?"**

### The Core Architectural Principle: Server-First Canonical Rendering
1. **Single Source of Truth**: Desktop and Web share the exact same backend engine (`ProfessionalDocumentRenderer` & `ExcelTemplateRenderer`). Any design change or custom PDF Studio / Excel Studio template updated in Desktop instantly reflects on Web without duplicating code or maintaining two divergent layout engines.
2. **2-Way Document Generation Flow (Identical to Desktop)**:
   - **Way 1 (Custom Studio Template)**: If an active custom template is designated as default in PDF Studio or Excel Studio (`TemplateStorageService.defaultFor(type)` / `/api/pdf-studio/templates`), the server renders using that custom template (`PdfStudioRenderer` / `ExcelTemplateRenderer.render`).
   - **Way 2 (Standard Built-In Engine)**: If no custom template is active, or if rendering encounters any error, the server gracefully falls back to the standard professional built-in engines (`ProfessionalDocumentRenderer` for PDF and `ExcelTemplateRenderer.renderBuiltIn` with `starterWorkbook` for Excel).
3. **100% Visual & Structural Parity**:
   - Both Desktop and Web download the exact identical byte-for-byte PDF and XLSX files:
     - **Excel**: Official company header, logo, dark blue header (`#193a74`), item columns, tax breakdown (CGST/SGST/IGST), amount in words (`INR : ...`), and authorized signatory block.
     - **PDF**: Official A4 layout, vector typography, GST summary tables, and authorized signatory.
4. **Resilient Web Client**:
   - The Web frontend calls `GET /api/documents/render?type={TYPE}&number={NO}&format={PDF|XLSX}`.
   - For offline or network edge cases, lightweight client-side generators (`DocumentPdfGenerator.js` and `DocumentExcelGenerator.js`) act as seamless secondary fallbacks.

## 2. Root Cause Analysis

### Root Cause 1: Error *"Canonical output is currently supported for Sales Invoice and Purchase Invoice"*
- **Location**: `CanonicalDocumentService.java:251-260` in Desktop Server (`DSE-ERP-10.0.25`).
- The method `parseType(String value)` strictly rejected all types other than `SALES_INVOICE` and `PURCHASE_INVOICE`:
  ```java
  private static DocumentType parseType(String value) {
      String n = value == null ? "" : value.trim().toUpperCase(Locale.ROOT).replace('-', '_').replace(' ', '_');
      return switch (n) {
          case "SALE", "SALES", "SALES_INVOICE" -> DocumentType.SALES_INVOICE;
          case "PURCHASE", "PURCHASES", "PURCHASE_INVOICE" -> DocumentType.PURCHASE_INVOICE;
          default -> throw new IllegalArgumentException(
                  "Canonical output is currently supported for Sales Invoice and Purchase Invoice.");
      };
  }
  ```
- **Consequences**:
  - `CreditDebitNoteController.js:426`: Clicking "Print / PDF" called `/api/documents/render?type=CREDIT_NOTE...`, throwing HTTP 400.
  - `QuotationController.js:870`: WhatsApp link shared `/api/documents/render?type=QUOTATION...`, which failed when opened.
  - `ReturnsController.js`: Lacked direct PDF download and called browser `window.print()` instead of `/api/documents/render`.

### Root Cause 2: Returns Email Sending Missing PDF Attachment
- In `ReturnsController.js:689-705`, `sendEmailPrompt` called `OperationsService.sendAuthorityEmail` passing `recipientEmail` with `attachmentBase64: null`.
- The backend `BusinessEmailController.java` requires `r.recipient()` and base64 attachment data to dispatch attachments. Without base64 payload, emails arrived without the document attached.

### Root Cause 3: Excel Format Mismatch Between Desktop and Web
- **Desktop Architecture (`ExcelTemplateStorageService.java:38-86`, `ExcelTemplateRenderer.java`)**:
  Desktop produces formatted `.xlsx` workbooks containing:
  1. Company Branding Header: Logo, Company Name (18pt bold, merged Col 1–7), Address, GSTIN, Phone, Email.
  2. Document Metadata Block: Document Number & Date, Party Name & GSTIN, Delivery Address, Reference/Terms.
  3. Styled Column Headers: Dark Blue background (`#193a74`), bold white text, exact column widths `{12, 34, 14, 10, 10, 14, 12, 16}`.
  4. Itemized Grid: Serial, Description with line remarks, HSN, Quantity, Unit, Rate, Discount, GST %, Taxable Value.
  5. Totals Block: Subtotal, CGST, SGST, IGST, Round Off, Grand Total formatted as `#,##0.00`.
  6. Amount in Words: Merged full-width row ("Rupees ... Only" / "INR : ...").
  7. Authorized Signatory: Company Signature & Signatory block.
- **Current Web Defect**:
  In both `ReturnsController.js` and `QuotationController.js`, Excel export was generating an unstyled, barebones table dump with plain text, no company details, no dark-blue headers, no tax split, no amount in words, and no signatory section.
- In `view-sales-returns`, the "Export" button in the view-header was completely missing compared to `view-purchase-returns`.

### Phase 2: Web Application Updates (`d:\ERP Website\admin`)

#### 2.1 Utility Services (`js/util/`):
- `DocumentPdfGenerator.js`: Client-side fallback PDF generator with high-fidelity parity to `ProfessionalDocumentRenderer.java`.
- `DocumentExcelGenerator.js`: Client-side fallback Excel generator matching Desktop starter workbook (branding header, dark blue `#193a74` table headers, totals, amount in words, signatory).

#### 2.2 In `ReturnsController.js`:
- `downloadPdf(no)`: Fetches `/api/documents/render?type=SALES_RETURN&number=${no}&format=PDF` (or `PURCHASE_RETURN`) via `ApiService`. On failure, falls back to `DocumentPdfGenerator`.
- `downloadExcel(no)`: Fetches `/api/documents/render?type=SALES_RETURN&number=${no}&format=XLSX` (or `PURCHASE_RETURN`). On failure, falls back to `DocumentExcelGenerator`.
- `sendEmailPrompt(no)`: Fetches PDF blob from `/api/documents/render`, converts to base64, attaches to payload (`attachmentName`, `attachmentBase64`, `recipient`), and sends email.
- `sendWhatsappPrompt(no)`: Opens WhatsApp dialog with party phone number and document summary.
- Header Export buttons: Enhanced to generate formatted workbooks.

#### 2.3 In `QuotationController.js`:
- `printPdf(no)`: Fetches `/api/documents/render?type=QUOTATION&number=${no}&format=PDF` and triggers browser preview/download.
- `downloadExcel(no)`: Fetches `/api/documents/render?type=QUOTATION&number=${no}&format=XLSX`.
- `sendEmailPrompt(id, no, email)`: Fetches quotation PDF blob from server, attaches base64, and dispatches.
- `sendWhatsappPrompt(id, no, phone)`: Shares quotation details directly without broken canonical URLs.

#### 2.4 In `CreditDebitNoteController.js`:
- `downloadPdf(noteNo, isCredit)`: Calls `/api/documents/render?type=CREDIT_NOTE...` now fully supported by server backend.
