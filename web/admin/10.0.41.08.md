# Web Studio v10.0.41.08 Specification & Architecture Plan

## 1. Executive Summary & Problem Scope

This document defines the root-cause analysis, desktop ERP parity verification, architectural designs, and implementation steps for **Release v10.0.41.08** of the Jasvi Industries Web Studio.

### Issues to Resolve
1. **Sales Register Purple Actions Button Dead:** The `::: Actions` dropdown button in Sales Register table rows is unresponsive and does not display the 13-action context menu.
2. **Record Payment Master Lookups Hanging:** Payment Mode and Bank Account dropdowns on the Invoice Payment screen (`view-record-payment`) display placeholder text (*"Loading modes from master lookup..."* / *"Loading bank accounts..."*) instead of live database records. No dummy/mock data permitted.
3. **Settings Email Configuration Deserialization Error:** Saving SMTP email delivery settings throws:
   `Request payload could not be read or contains invalid data formats. • Cannot map 'null' into type 'boolean' ... (through reference chain: org.example.server.authority.BusinessEmailController$Settings["passwordConfigured"])`. Date formatting across screens must strictly remain bound to global setting format without regressions.
4. **Sale & Purchase Creation Attachment Panel Misplacement:** The standardized attachment widget was erroneously placed in the middle of the document form (above line items). It must be restored to its desktop-parity location at the bottom-right in the *Notes & Attachment* card.
5. **Universal Semantic Amount Coloring:** Across all tables and detail drawers, monetary figures must match the Sales Register color coding:
   - **Total / Invoiced:** Crisp White / Bright Cyan (`var(--cyan)`)
   - **Paid / Received / Inflow / Credit:** Emerald Green (`#34d399`)
   - **Pending / Balance / Due / Outflow:** Amber Yellow (`#fbbf24`) / Coral Red (`#f87171` if overdue/pending balance)
6. **"Same as Billing Address" Interlocking Defect:** In both Sale and Purchase creation, Delivery Address and Delivery GSTIN remain editable upon first opening or party selection even though *"Same as Billing"* is checked by default. It only becomes read-only after manually unticking and re-ticking the checkbox.
7. **Interactive Decision Dialog Enhancement:** Transition away from transient 3-second toast notifications for confirmations, warnings, and export generation into user-friendly modal dialogs where users can make explicit decisions.

## 2. Root Cause Analysis & Desktop Parity Investigation

### Issue 1: Sales Register Purple Action Button
- **Root Cause:** In `views/sales-register.html`, `#sales-row-actions-menu` was positioned inside `<div id="sales-detail-drawer" style="display: none; ...">`. Because the parent drawer has `display: none;`, all child elements within it are hidden, regardless of whether `classList.add('show')` is called. Furthermore, a duplicate `#sales-row-actions-menu` remained in `views/sale-create.html`, causing DOM selector collisions.
- **Desktop Parity:** In JavaFX Desktop (`SalesRegisterController.java` & `ProfessionalUiEnhancer.java`), the row actions popup is attached directly to the global window stage (`ContextMenu` / `Stage.getOwner()`), independent of any slide-out drawers.
- **Resolution:** Relocate `#sales-row-actions-menu` to the root of `views/sales-register.html` (or global floating root in `index.html`) outside the hidden detail drawer, with `z-index: 100020`. Remove the duplicate element from `views/sale-create.html`.

### Issue 2: Record Payment Master Lookups Hanging
- **Root Cause:** In `RecordPaymentController.js`, `await this.loadPaymentLookups()` was executed at line 178 *before* `NavigationRouter.selectNav('view-record-payment')` (line 202). When navigating for the first time, `views/record-payment.html` was not yet mounted in the DOM, so `document.getElementById('rp-pay-mode')` and `document.getElementById('rp-bank-account')` were `null`. Furthermore, `NavigationRouter.js:454` only called `refreshPayments()` on view mount and never invoked `loadPaymentLookups()`.
- **Desktop Parity:** In JavaFX Desktop (`RecordPayment.fxml` & `PaymentDialogController.java`), master lookups for categories `PAYMENT_MODE` and `BANK_ACCOUNT` (with `BANK` fallback) are queried from `master_category` and `lookup_master` via `MasterDataService.lookups("PAYMENT_MODE")` and `MasterDataService.lookups("BANK_ACCOUNT")`.
- **Resolution:**
  1. In `NavigationRouter.js` (`case 'view-record-payment'`), invoke `RecordPaymentController.loadPaymentLookups()`.
  2. In `RecordPaymentController.open()`, ensure `selectNav('view-record-payment')` completes view hydration before calling `loadPaymentLookups()`.
  3. Query `MasterService.getLookupsByCategoryCode('PAYMENT_MODE')` with fallback to `MasterService.getLookups('PAYMENT_MODE')` and `PAYMENT MODE`.
  4. Query `MasterService.getLookupsByCategoryCode('BANK_ACCOUNT')` with fallback to `'BANK'` and `getLookups('BANK_ACCOUNT')`.

### Issue 3: Settings Email Configuration Deserialization Error
- **Root Cause:** In `BusinessEmailController.java`:
  ```java
  public record Settings(String email, String appPassword, String host, Integer port, boolean passwordConfigured) {}
  ```
  The parameter `passwordConfigured` is a primitive `boolean`. When `SettingsController.js:1023` sends `PUT /api/authority/email/settings`, it omits `passwordConfigured`. Jackson's default deserializer attempts to inject `null` into a primitive `boolean`, failing with `Cannot map null into type boolean`.
- **Desktop Parity:** In Desktop `SettingsController.java:2750`, the payload submitted to the server includes `current.passwordConfigured()`.
- **Resolution:**
  1. In `SettingsController.js`, track `this.serverPasswordConfigured = !!res.passwordConfigured` upon loading email settings.
  2. In `saveEmailSettings()`, include `passwordConfigured: Boolean(this.serverPasswordConfigured || (password && password.trim()))` in `smtpPayload`.
  3. Preserve all existing date format settings and handlers (`DatePickerFormatter.js`, `FormatUtil.js`) intact.

### Issue 4: Sale & Purchase Creation Attachment Panel Misplacement
- **Root Cause:** The new standardized attachment card was injected into the left column of `views/sale-create.html` (lines 134–157) and `views/purchase-creation.html` above the item tables, while the original bottom-right sidebar card (`#ws-card-notes` / `#pe-card-notes`) remained untouched with redundant controls.
- **Desktop Parity:** In Desktop `CreateSale.fxml` and `PurchaseInvoice.fxml`, the right sidebar features three vertical cards: *Summary*, *Tax & Transport*, and *Notes & Attachment*. Attachment management resides inside the third card at the bottom right.
- **Resolution:**
  1. Remove the center attachment cards from `views/sale-create.html` and `views/purchase-creation.html`.
  2. In both views' right sidebar `#ws-card-notes` and `#pe-card-notes`, replace the old attachment inputs with the standardized 3-button design (`+ Add / Replace`, `👁 Preview`, `🗑️ Delete`) and clean dropzone indicator matching Image 3 and Settings.

### Issue 5: Universal Semantic Amount Coloring
- **Root Cause:** `TableUiEnhancer.js:143` applied `td.classList.add('cell-money-green')` uniformly to all monetary cells without evaluating column context or document balance state.
- **Desktop Parity:** In JavaFX Desktop `SemanticTableCells.java` and `SalesRegisterController.java`:
  - Paid/Received/Inflow = Emerald Green (`#34d399`)
  - Balance/Pending/Due/Outflow = Amber (`#fbbf24`) or Red (`#f87171` when pending > 0)
  - Total/Net = Crisp White or Cyan (`var(--cyan)`)
- **Resolution:** Update `TableUiEnhancer.js` and register controllers to inspect column headers and data semantic roles (`paid`, `received`, `credit`, `pending`, `balance`, `due`, `debit`, `total`), applying appropriate colors dynamically.

### Issue 6: "Same as Billing Address" Interlocking Defect
- **Root Cause:**
  1. In `views/sale-create.html` and `views/purchase-creation.html`, delivery inputs lacked initial `readonly` attribute in static HTML.
  2. In `SalesController.js:1145` and `PurchaseController.js:1581`, the initialization routine looped through all inputs and set `el.readOnly = false` when not in read-only mode, overriding the lock.
  3. Selecting a party (`onWorkspaceCustomerChange` and `onEditorSupplierChange`) populated values but never called `toggleSameAddress(true)`.
- **Desktop Parity:** In Desktop `CreateSaleController.java:540`, when `chkSameAsBilling.isSelected()`, delivery fields are disabled and bound via listener to billing inputs.
- **Resolution:**
  1. Enforce `readonly` and disabled styling on Delivery Address and Delivery GSTIN in HTML templates.
  2. After input initialization loops in `SalesController.js` and `PurchaseController.js`, invoke `toggleSameAddress(chkSame.checked)` and `onSameAsBillingToggle(chkSame.checked)`.
  3. Ensure party selection handlers invoke the interlocking toggle function.

### Enhancement: Interactive Decision Dialogs
- **Current State:** Many actions rely on `showToast(...)` or browser native `alert()`, providing no interactive choice and vanishing automatically.
- **Architecture:** Leverage and expand `AppDialogService.js` to provide:
  - `confirm(title, heading, message, primaryAction, safeAction)`: Returns `Promise<boolean>`.
  - `decision(options)`: Rich modal with customizable buttons (e.g., Export format selection, Review / Discard, Retry / Cancel).
  - Replace transient toast notifications on export actions (PDF/Excel) with a completed dialog offering `[ Open / View ]` and `[ Close ]`.
