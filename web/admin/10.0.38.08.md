**Desktop Baseline Revision**: `10.0.38`  
**Web Release Version**: `10.0.38.08` (Web Build #8)  
**Release Tag**: `web-v10.0.38.08`  
**Release Date**: 2026-10-21  
**Target Environment**: Production / Enterprise  

---

## 1. Executive Summary & Root Cause Analysis

### The Problem
Following release `v10.0.38.07`, the Web Studio login page experienced a critical issue where the login overlay would hang or remain stuck on the login screen ("just login") without transitioning to the workspace.

### Root Cause
1. **MutationObserver Recursion & UI Thread Starvation**:
   In `v10.0.38.07`, `DatePickerFormatter.initObserver()` attached an unthrottled `MutationObserver` directly to `document.body` observing `{ childList: true, subtree: true }`. Every single DOM mutation triggered `attachAll()` across all 60+ datepickers, which inserted wrapper elements and label badges. This DOM insertion generated secondary mutations, causing a cascading recursion loop that starved the JavaScript event loop and froze asynchronous login transitions (`hideAuthOverlay()`, `selectNav()`, `showToast()`).
2. **Invasive Prototype Tampering**:
   `Object.defineProperty(picker, 'value', ...)` intercepted native `HTMLInputElement.prototype.value` on all date inputs. In Chromium/WebKit engines, overriding the native `.value` descriptor can cause unexpected failures during form serialization, browser autofill, and input event dispatch.
3. **DOM Restructuring Disruptions**:
   Moving native inputs into wrapper `<div>` containers (`picker.parentNode.insertBefore(wrap, picker); wrap.appendChild(picker);`) changed direct parent-child relationships in `.form-group`, flexbox toolbars, and filter strips, interfering with form queries and layouts.

## 2. Desktop Application Parity & Architecture Solution

### Desktop Comparison (`DatePickerFormatter.java`)
In Desktop JavaFX, `DatePickerFormatter.java` does NOT alter the scene graph hierarchy, wrap controls in extra containers, or modify JavaFX internal prototypes. It simply synchronizes prompt text and editor formatting via safe event listeners and weak references.

### Web Engine Solution (v10.0.38.08)
1. **Zero-Invasive Non-Destructive Architecture**:
   - **No DOM Wrapping**: `<input type="date">` elements remain in their exact native DOM positions with their original parent hierarchy untouched.
   - **No Prototype Overriding**: Remove all `Object.defineProperty` tampering on `HTMLInputElement.prototype.value`. Native input `.value` remains completely untouched and standard ISO `YYYY-MM-DD`.
   - **No Transparent Text Masking**: Remove `color: transparent !important` from `css/app.css` so datepickers always render normally and legibly.
2. **Safe Formatted Indicator & Synchronized Feedback**:
   - Keep inputs native and readable.
   - Synchronize formatted date badges (`[dd/MM/yyyy]`) and descriptive tooltips displaying the exact formatted date according to `company.dateFormat` (e.g. `Business Date: 21/10/2026 [dd/MM/yyyy]`).
   - For filter strips, append an unobtrusive formatted preview indicator (`.erp-date-value-preview`) that reflects `FormatUtil.formatDate(picker.value)` in real time.
3. **Strict Observer Isolation & Debouncing**:
   - Remove the unthrottled `MutationObserver` on `document.body`.
   - Never observe or touch elements inside `#auth-overlay`.
   - Debounce all dynamic DOM rescans using `requestAnimationFrame` with an `isEnhancing` re-entrancy lock, matching `GlobalUiEnhancer.js`.
4. **Complete Login Page Restoration**:
   - Verify that `setupAuthForms()`, `populateLoginRoles()`, `handleLoginSubmit()`, and `handlePostLoginSuccess()` execute cleanly without any CPU choke or event loop starvation.

## 3. Planned Changes by File

### 1. `js/util/DatePickerFormatter.js`
- Remove DOM re-wrapping (`insertBefore`, `appendChild`, `.dse-datepicker-wrap`).
- Remove `Object.defineProperty` on `picker.value`.
- Implement safe, non-invasive date format synchronization with `isEnhancing` guard and 150ms debounce.
- Ensure `#auth-overlay` is strictly excluded from all datepicker processing.

### 2. `css/app.css`
- Remove the invasive `.dse-datepicker-wrap input[type="date"] { color: transparent !important; }` rules.
- Add clean styles for `.erp-date-value-preview` and `.erp-date-format-badge`.

### 3. `index.html`
- Bump version badges to `Version 10.0.38.08` (auth overlay, app header, user profile menu).
- Update all script and stylesheet cache busters to `?v=10.0.38.08a`.

### 4. `version.json` & `js/version.js`
- Bump `webBuild` to `8`.
- Bump `webVersion` and `tag` to `10.0.38.08` / `web-v10.0.38.08`.
