## 1. Executive Summary & Defect Root Cause Analysis

During user testing of the Data Import Studio with `Sales_Template1.xlsx`, row 1 (`JI/25-2026/0163`) was skipped as duplicate (existing in database), while row 2 (`JI/25-2026/0164`) returned the following error:

```text
Errors Encountered (1):
• JI/25-2026/0164: Request payload could not be read or contains invalid data formats. • Cannot map `null` into type `boolean` (set `DeserializationFeature.FAIL_ON_NULL_FOR_PRIMITIVES` to 'false' to allow) at [Source: REDACTED (`StreamReadFeature.INCLUDE_SOURCE_IN_LOCATION` disabled); byte offset: #1018] (through reference chain: org.example.server.operations.OperationDtos$SaleDto["emailSent"])
```

### Why Was This Error Thrown?
1. **Enhanced Exception Transparency Proved Root Cause**:
   - In previous builds, this error was swallowed by the generic server catch-all: *"The ERP server could not complete this operation. Check the server log for the underlying error."*
   - Our enhanced exception handler in `ApiExceptionHandler.java` caught `HttpMessageNotReadableException` and extracted the exact Jackson deserialization chain, pinpointing `OperationDtos.SaleDto["emailSent"]`.
2. **Java Record Canonical Constructor Constraint**:
   - In Spring Boot server `OperationDtos.java`:
     ```java
     public record SaleDto(Integer id, String invoiceNo, String invoiceDate, PartyDto customer, double subtotal, double discountAmount, double gstAmount, double totalAmount, String remarks, String createdAt, boolean emailSent, String dueDate, double paidAmount, String paymentStatus, boolean whatsappSent, String invoiceType, String salesperson, String source, String notes, String deliveryAddress, String paymentTerms, String transporter, String referenceNo, String poDate, String billingAddress, String gstType, String doorDelivery, String vehicleNumber, String contactPerson, String transportNote, String orderNo, String gstin, String billingGstin, String deliveryGstin, boolean sameAsBilling, String transporterGstin, String chargeType, double chargeAmount, String contactPersonMobile, String documentStatus, String attachmentPath, double quantity, List<ChargeDto> charges, List<LineDto> lines, long rowVersion)
     ```
   - Notice that `emailSent` and `whatsappSent` are declared as primitive `boolean` (not wrapper `Boolean`).
   - In Spring Boot, Jackson's default configuration enforces `FAIL_ON_NULL_FOR_PRIMITIVES`.
   - When Web `ImportService.js` constructed `salePayload`, it omitted `emailSent`, `whatsappSent`, `chargeType`, `chargeAmount`, `orderNo`, etc.
   - When Jackson attempted to construct `SaleDto` from JSON missing `emailSent`, it encountered `null` for a primitive `boolean` and immediately failed with `InvalidNullException`.
3. **Purchase Loader Contract Also Impacted**:
   - In `OperationDtos.PurchaseDto`, `boolean emailSent` and `boolean sameAsBilling` are also primitives.
   - Web `ImportService.js` omitted `emailSent` in `purchasePayload`, which would trigger the identical Jackson error on Purchases import.
