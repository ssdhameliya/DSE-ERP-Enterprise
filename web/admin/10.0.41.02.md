## 1. Executive Summary & Problem Statement

Upon browser refresh (or direct URL entry), the Web Admin application exhibited jarring visual layout shifts (FOUC), stale data flashing, and screen leaking:
1. **Header Company Name Flash:** Statically displayed `JASVI INDUSTRIES` before jumping to `JASVI CREATION` (or any dynamic company name configured in Settings).
2. **Top 4 Action Badges False-Zero Flash:** Reminder, Notification, Email, and WhatsApp icon buttons displayed bright red/cyan `(0)` badges on load before vanishing or showing real counts.
3. **Top 6 KPI Cards Layout Shift & Subtext Distortion:** KPI cards loaded in a squished, overlapping 3-row layout with subtext (`"37 active sales invoices"`) before `KpiCardEnhancer.js` demolished and rebuilt them into 58px ribbon cards.
4. **Header Live Clock & Date Flash:** Clock flashed hardcoded dummy placeholder `12:00:00 PM` before jumping to live system date and time.
5. **Footer Bar Stale Data Flash:** Footer flashed historical hardcoded text (`Jasvi Industries`, `info@jasviindustries.in`, `Sunday, 18 Oct 2026`) before jumping to dynamic company settings.
6. **Universal Cross-Screen Sub-Route Flash:** Refreshing on any sub-route (`#purchase-register`, `#bank-entry`, `#sales-register`, etc.) momentarily rendered the Dashboard before abruptly jumping to the requested screen.
7. **Login / Auth Screen Refresh Leak:** Refreshing on the login screen flashed the ERP workspace in the background before `#auth-overlay` covered it, and login footer items popped in late.
8. **Workspace Tab Bar Blank Flash:** On refresh, workspace tabs (`[Dashboard]`, `[Purchase Register ×]`, etc.) were absent during the initial frame and only popped in after all 54 JavaScript files loaded.

## 3. Detailed Technical Implementation Plan

### Step 1: Pre-Paint Synchronous State & Route Hydration (`<head>`)
Place a robust, zero-dependency inline script at the top of `<head>` in `index.html` (after theme check, before any visible body content is parsed):
1. **Dynamic Branding Hydration:**
   - Read `localStorage.getItem('dse_branding')`.
   - If present, resolve company name. Set a dynamic CSS variable or inject an immediate pre-render rule so `.app-header .brand-title` renders the user's active company name on Frame 0 without hardcoding any static string.
2. **Immediate Route Resolution:**
   - Read `window.location.hash`.
   - Map hash (`#purchase-register`, `#bank-entry`, `#sales-register`, etc.) to target view ID.
   - Inject an early pre-layout stylesheet:
     ```css
     #view-target { display: block !important; }
     #view-target.fixed-viewport { display: flex !important; }
     .module-view:not(#view-target) { display: none !important; }
     ```
   - **Result:** The browser natively paints the target view directly on Frame 0. The Dashboard **never renders** unless `#dashboard` was actually requested.
3. **Authentication Guard:**
   - If `!localStorage.getItem('dse_access_token')`, enforce `document.documentElement.classList.add('auth-required')`.
   - In `<head>` CSS: `html.auth-required #auth-overlay { display: flex !important; z-index: 999999 !important; }` and `html.auth-required #app-container { display: none !important; }`.

### Step 2: Remove All Fake Placeholders & Apply Desktop Parity Defaults
In `index.html`:
1. **Badges:**
   - Add `.zero` class to all 4 shell badge counters:
     `<span class="header-badge-counter zero" id="badge-reminders"></span>`
     `<span class="header-badge-counter zero" id="badge-notifications"></span>`
     `<span class="header-badge-counter zero" id="badge-email"></span>`
     `<span class="header-badge-counter zero" id="badge-whatsapp"></span>`
   - Badges start completely hidden (`display: none;`). Only when real counts $> 0$ are received does JavaScript remove `.zero` to reveal the count (100% desktop `applyBadge()` parity).
2. **Live Clock:**
   - Remove fake `12:00:00 PM`. Replace with clean, formatted current client timestamp on initial parse or subtle pulse dot.
3. **Footer:**
   - Match `SharedApplicationFooter.java`: Remove hardcoded `"Sunday, 18 Oct 2026"`, `"Jasvi Industries"`, and `"info@jasviindustries.in"`.
   - Dynamic footer fields start empty (`""`) and populate synchronously from stored settings.
4. **Header Brand:**
   - Tokenize `.brand-title` with an ID (`header-brand-title`) so it hydrates dynamically from the saved branding profile rather than flashing `"JASVI INDUSTRIES"`.

### Step 3: Structural Parity for Top 6 KPI Cards
In `index.html:L950-L1005`:
- Update the static HTML of the 6 Dashboard KPI cards so that they **natively match the 58px ribbon markup** (`compact-kpi-card`, icon bubble, 2-row layout).
- In `KpiCardEnhancer.js`:
  - When enhancing cards that already conform to the compact layout, preserve the existing markup and update only classes/attributes.
  - Eliminate runtime `innerHTML` destruction so that cached metrics are painted into a pre-aligned, non-colliding layout from Frame 0.

### Step 4: Boot Event Acceleration
- In `app.js:L1810`:
  - Change initialization trigger from `window.addEventListener('load')` to `document.addEventListener('DOMContentLoaded')`.
  - Ensures routing, shell badges, and controllers initialize within **50ms–100ms** rather than waiting 2.5 seconds for external PDF/Excel libraries and fonts to finish.

### Step 5: Version Bump & Cache Invalidation
- Bump `version.json` and `js/version.js` to `10.0.41.02` (`webBuild: 2`).
- Update all 54 script and stylesheet cache-buster parameters in `index.html` to `?v=10.0.41.02`.
