## 1. Executive Summary & Problem Root Cause Analysis
Per `prinical.md` (Rules 1-14) and `MANDATORY_DEVELOPMENT_PROTOCOL.md`, this specification analyzes and resolves the datepicker formatting defect reported by the user comparing Desktop vs Web:

### Root Cause 1: Formatted Date Showing on Top in Label
- **Desktop Parity Architecture (`DatePickerFormatter.java`)**:
  On Desktop, JavaFX `DatePicker` uses a `StringConverter` to format the internal text editor (`picker.getEditor().setText(BusinessClock.formatDate(value))`), rendering `21 Apr 2026` directly **inside** the datepicker box. The `<label>` above remains clean: `📅 From Date` and `📅 To Date`.
- **Current Web Issue (`10.0.38.10`)**:
  In `DatePickerFormatter.js:61-93`, `updateLabelBadge()` appended `<span class="erp-date-format-badge">[21 Apr 2026]</span>` into the parent `<label>`, cluttering the top header with a bracketed format badge instead of formatting inside the box.

### Root Cause 2: Double Calendar Icon (`📅 📅 From Date`)
- **Current Web Issue (`10.0.38.10`)**:
  In `index.html` (e.g. line 1238), the label text already contains the calendar icon as raw text: `<label>&#128197; From Date</label>`.
  `LabelIconEnhancer.js` only checked whether a child `span:first-child` had an emoji. Since the emoji was raw text, it inserted another `span.label-icon`, producing duplicate icons: `📅 📅 From Date`.

### Solution Architecture (`10.0.38.11`):
1. **Remove Top Label Badge**: Eliminate `updateLabelBadge()` from `DatePickerFormatter.js` and clean up any existing badge spans.
2. **Prevent Duplicate Icons**: In `LabelIconEnhancer.js`, test the entire label text (`/[\u{1F300}-\u{1F9FF}\u{2600}-\u{26FF}]/u.test(text)`). If an icon is already present in raw text or HTML, skip icon injection.
3. **In-Field Formatted Date Display (`21 Apr 2026`)**:
   Wrap date inputs in `.erp-date-field-container` with an in-field formatted text overlay (`.erp-date-display-val`) showing `21 Apr 2026` directly inside the input box matching Desktop.
   Keep native `<input type="date">` underlying value as ISO `YYYY-MM-DD` so zero backend Spring Boot APIs or controller filter queries break.
