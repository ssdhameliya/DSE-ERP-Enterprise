## 1. Executive Summary & Forensic Root Cause Analysis

Following user feedback on `v10.0.41.10` and detailed inspection of the 4 live production screenshots, a deep script-driven audit was executed across all 42 views, 26 controllers, 11 services, and 3 stylesheet modules. The audit uncovered the exact mechanical root causes behind every reported issue:

| Issue Reported by User | Forensic Root Cause in Codebase | Scope & Impact |
| :--- | :--- | :--- |
| **1. Amounts in many tables are still plain white (Purchase Register, Purchase Recon, etc.)** | **Dual Root Cause:**<br>1) In `css/app.css`, `:root` and `body.light-theme` **NEVER defined the semantic variables `--yellow:`, `--green:`, `--red:`, `--purple:`, `--amber:`, `--orange:`**. Controllers setting `style="color:var(--yellow);"` or `style="color:var(--green);"` evaluated undefined variables, discarding the color and falling back to white (`#f8fafc`) in dark mode or black in light mode.<br>2) `TableUiEnhancer.js` added classes `.amount-green`, `.amount-red`, `.amount-yellow`, `.amount-cyan`, but **these CSS classes were never written in `app.css`**.<br>3) In `GlobalUiEnhancer.js`, the `MutationObserver` explicitly ignored `TBODY`, `TR`, `TD`, meaning when controllers re-rendered data via `tbody.innerHTML = ...`, `TableUiEnhancer` was never invoked on the updated rows. | All 90 tables across 42 views and modals. |
| **2. Side panel labels and amounts lack color and 3D icons** | 1) Side panels use `<span class="drawer-field-label">` and `<span class="drawer-field-value">` (or custom `<div>` grids). `LabelIconEnhancer.js` strictly queried `<label>`, completely ignoring drawer labels.<br>2) Drawer amounts (`#pd-amount`, `#pd-paid`, `#pd-balance`) used `var(--yellow)`, `var(--green)`, `var(--red)`, which were undefined in CSS, so amounts appeared plain white.<br>3) Drawer action buttons (`Record Payment`, `View PDF`, `View Excel`, `Send Email`, `Edit`, `Close`) used generic `.btn-secondary` without 3D role gradients.<br>4) Dynamic drawer did not collapse empty/blank fields and did not limit quick actions to the top 4–5 contextual actions. | 17 views with side drawers (128+ drawer fields). |
| **3. Top panel Purchase Register heading and tabs lack color & polish** | 1) `.view-header`, `.view-title-group h1`, and `.view-title-group p` had bare minimal styles with plain white text and raw emoji `<span>📦</span>` with no 3D badge styling, no glowing border, and no accent lighting.<br>2) The top multi-document workspace tab strip (`.workspace-tab`) had dull flat slate pills without 3D tactile elevation, active glowing border, or icon badges.<br>3) View action buttons like `↻ Refresh` used plain `.btn-secondary` rather than 3D sapphire role gradients (`role-refresh`). | All 42 view headers and the global workspace tab bar. |
| **4. Purchase Reconciliation (PRC) layout, date presets, default FY dates & pagination** | 1) **Wasted Space & Layout Anomaly:** The filter toolbar had an awkward 2-row layout with a redundant duplicate `+ New Purchase Recon` button in row 1, while the top header already had `+ New Purchase Recon`. Furthermore, the 6-card KPI ribbon was positioned *under* the filter toolbar instead of on top.<br>2) **Date Preset Buttons Not Working:** `views/purchase-recon.html` sent lowercase strings (`'today'`, `'month'`, `'all'`), but `PurchaseReconController.js` lines 136–156 checked uppercase (`'TODAY'`, `'THIS_MONTH'`, `'ALL'`), so all conditions failed and did nothing.<br>3) **Period From/To Blank on Load:** Date inputs `#pr-date-from` and `#pr-date-to` started empty instead of defaulting to Start of Financial Year (`01 Apr 2026`) through as of Today (`24 Oct 2026`), formatted according to Company Settings (`FormatUtil.getBusinessDateFormat()`).<br>4) **Hardcoded Stale Pagination:** `#pr-pagination-info` showed hardcoded `Showing 0 of 0 records` because `PurchaseReconController.js` never updated it, and the controls were primitive Prev/Next buttons instead of the 2027 enterprise pagination bar. | `views/purchase-recon.html` and `PurchaseReconController.js`. |
| **5. Settings page top tabs have mismatched, chaotic colors** | `ButtonIconEnhancer.js` treated all `<button>` tags as action buttons. Because tab text included words like "Payment" (`Payment & Bank`) and "Email" (`Email Delivery`), `ButtonIconEnhancer` mistakenly assigned `.role-payment` (bright green) and `.role-email` (bright blue), while other tabs received neutral gray. All navigation tabs (`.settings-tab-btn`, `.register-tab-btn`, `.tab-btn`, `.workspace-tab`) must be excluded from action button decorations and given a unified 2027 navigation tab design system. | 8 views with tabbed navigation (50 navigation tabs). |
| **6. Action buttons show double icons (`⚡ ::: Actions`)** | In 28 places across 15 controllers, buttons rendered literal `::: Actions`. `ButtonIconEnhancer.js` only checked for Unicode emojis, missing `:::`, `⋮`, `▾`, prepending `⚡` to produce `⚡ ::: Actions`. | 28 table action buttons. |
| **7. Dialog shows OK and Cancel on informational alerts** | `#modal-app-dialog` hardcoded both Cancel and Continue buttons. Informational alerts (`info`, `alert`, `success`, `error`) did not explicitly hide Cancel. | Central semantic dialog and all modal dialogs. |
| **8. Raw browser popups instead of centralized modal** | 263 direct calls to native browser `alert()`, `confirm()`, and `prompt()` exist across controllers without interception. | 263 call sites across 13 files. |
| **9. Hard Rule: Dark & Light Mode Parity** | Semantic colors must look rich, vibrant, and luminous in dark mode, and deep, saturated, WCAG AAA compliant (4.5:1+ contrast) in light mode. | Universal across all screens. |
| **10. Bank Statement Refresh Error & Missing KPI Icons** | 1) The Refresh button called `loadBatch(window.BankStatementController.currentBatchId)`. `currentBatchId` was never exported from the controller closure, so it passed `undefined`, triggering `NumberFormatException: For input string: "undefined"`.<br>2) The 8 KPI cards in `views/bank-statement.html` were missing `<div class="kpi-icon-bubble">` icons and had hardcoded `data-erp-kpi-compact-enhanced="true"`, preventing `KpiCardEnhancer` from enhancing them. | `views/bank-statement.html` and `BankStatementController.js`. |

## 3. Targeted Technical Solutions & Architectural Specifications

### A. Universal Table Amount Colorization Architecture
1. **Define Semantic Variables in `:root` and `body.light-theme` (`css/app.css`):**
   ```css
   :root {
     /* Dark Theme Semantic Palette */
     --green: #10b981;
     --emerald: #10b981;
     --yellow: #f59e0b;
     --amber: #f59e0b;
     --red: #ef4444;
     --purple: #8b5cf6;
     --blue: #3b82f6;
     --cyan: #38bdf8;
     --teal: #14b8a6;
     --orange: #f97316;
   }

   body.light-theme {
     /* Light Theme Semantic Palette (High-Contrast WCAG AAA) */
     --green: #059669;
     --emerald: #047857;
     --yellow: #d97706;
     --amber: #d97706;
     --red: #dc2626;
     --purple: #7c3aed;
     --blue: #2563eb;
     --cyan: #0284c7;
     --teal: #0f766e;
     --orange: #c2410c;
   }
   ```
2. **Add Forced Amount Utility Classes with `!important` (`css/app.css`):**
   ```css
   .amount-green  { color: var(--green) !important; font-weight: 700 !important; font-family: 'JetBrains Mono', monospace !important; }
   .amount-red    { color: var(--red) !important; font-weight: 700 !important; font-family: 'JetBrains Mono', monospace !important; }
   .amount-yellow { color: var(--yellow) !important; font-weight: 700 !important; font-family: 'JetBrains Mono', monospace !important; }
   .amount-cyan   { color: var(--cyan) !important; font-weight: 700 !important; font-family: 'JetBrains Mono', monospace !important; }
   .amount-purple { color: var(--purple) !important; font-weight: 700 !important; font-family: 'JetBrains Mono', monospace !important; }
   ```
3. **Upgrade `TableUiEnhancer.js` & `GlobalUiEnhancer.js`:**
   - In `TableUiEnhancer.js`, when coloring monetary cells:
     - Check child elements: pierce into child `<span>`, `<div>`, `<b>` so inline styled wrappers inherit the semantic color class.
     - Reset `td.dataset.erpCellEnhanced` when table rows change.
   - In `GlobalUiEnhancer.js`, update the `MutationObserver` so that when `TBODY` innerHTML is modified or `TR` elements are added/replaced, it debounces and executes `TableUiEnhancer.enhanceTable(table)`.
