## 1. Executive Summary & Design Objective

Per `prinical.md` (Rules 1-18), `MANDATORY_DEVELOPMENT_PROTOCOL.md` (Point 1 Full Parity, Point 6 Event Behaviors, Point 10 UI Symmetry & Consistency), and the user's specific request:
> *"when we send mail for quotation and both return it's give pop and ask email rather new Ui pop like sale and purcahse currently doing in normal sell and purcashe.. can we make the same like sell and purchase as here we have preview email and ect auto populayed .. can we do it and deployed it next version for web"*

### The Goal: Universal Rich Transmit Modal across All Transactions
1. **Eliminate Browser Prompts**: Completely eliminate raw browser `window.prompt()` alerts from Quotations, Sales Returns, and Purchase Returns.
2. **Unified Transmit Modal UI**: Share the identical, beautiful 3D card modal (`modal-email-invoice`) currently used in Sales and Purchase across:
   - **Sales Invoice**: `Transmit Tax Invoice via Email`
   - **Purchase Inward Bill**: `Transmit Purchase Inward Bill via Email`
   - **Quotation**: `Transmit Quotation Estimate via Email`
   - **Sales Return**: `Transmit Sales Return Credit Note via Email`
   - **Purchase Return**: `Transmit Purchase Return Debit Note via Email`
   - **Credit / Debit Notes**: `Transmit Credit/Debit Note via Email`
3. **Auto-Populated Intelligence**:
   - Automatically pre-fills **Recipient Email** from customer/supplier master record.
   - Automatically populates professional **Subject** line (`Quotation Estimate - QT-... | Jasvi Industries`).
   - Automatically drafts polite **Message Body** addressed to the specific client/supplier name with transaction total.
   - Automatically attaches document with real-time **`[👁 Preview PDF]`** action and green **`[ATTACHED]`** indicator badge.
   - Context-aware submit button (`✈ Send Quotation`, `✈ Send Credit Note`, etc.).

## 2. Desktop vs. Current Web Parity Audit (Actual vs. Expected)

| Screen / Feature | Current Web Build `10.0.39.01` (Actual) | Expected Result (`10.0.39.02`) |
|---|---|---|
| **Quotation Email Action** | Opens raw browser `window.prompt("Send Quotation ... to email address:")`. No preview, no subject editing, no custom body. | Opens rich `modal-email-invoice` modal with pre-filled recipient email, subject, custom greeting body, attached PDF card with `[👁 Preview PDF]`, and `[✈ Send Quotation]` button. |
| **Sales Return Email Action** | Opens raw browser `window.prompt()`. | Opens rich `modal-email-invoice` modal pre-filled with customer email, credit note adjustment subject, credit memo body, attached PDF with `[👁 Preview PDF]`, and `[✈ Send Credit Note]` button. |
| **Purchase Return Email Action** | Opens raw browser `window.prompt()`. | Opens rich `modal-email-invoice` modal pre-filled with supplier email, debit note adjustment subject, debit memo body, attached PDF with `[👁 Preview PDF]`, and `[✈ Send Debit Note]` button. |
| **Attached PDF Preview** | Not available from browser prompt. | Clicking `[👁 Preview PDF]` inside the email modal fetches real server PDF or activates `DocumentPdfGenerator` preview lightbox. |
| **Attachment Payload Delivery** | Sends base64 attachment only if prompt was completed, with no visual confirmation. | Dispatches `recipient`, `subject`, `body`, and base64 encoded PDF bundle through `OperationsService.sendAuthorityEmail` with loading button state and sound feedback. |
| **Row Action & Detail Drawers** | Row action menu and side drawers both called `sendEmailPrompt`. | All trigger points seamlessly invoke the universal `openEmailModal`. |

## 3. Implementation Blueprint

### Step 1: Enhance `SalesController.openEmailModal` into Universal Transmit Engine
Expand `openEmailModal(invoiceNo, docType, customDetails)` in `js/controllers/SalesController.js`:
- Add full support for `QUOTATION`:
  - Locate quotation from `QuotationController.quotationsCache` or `customDetails`.
  - Extract `customerEmail` / `email` (or lookup party from `MasterService.getParties()`).
  - Extract customer name and formatted amount (`FormatUtil.formatRupees`).
  - Set modal title: `Transmit Quotation Estimate via Email`.
  - Set subtitle: `Direct SMTP delivery of pricing proposal to client`.
  - Set subject: `Quotation Estimate - ${invoiceNo} | Jasvi Industries`.
  - Set body: Polite proposal letter citing quotation number, validity, and amount.
  - Set attachment name: `Quotation_${cleanNo}.pdf`.
  - Set send button label: `✈ Send Quotation`.
- Ensure `SALES_RETURN` and `PURCHASE_RETURN` dynamically update modal title, subtitle, and button labels (`✈ Send Credit Note` / `✈ Send Debit Note`).

### Step 2: Global Exposure & Routing in `QuotationController` and `ReturnsController`
- Expose `window.openDocumentEmailModal = (docNo, docType, details) => window.SalesController.openEmailModal(docNo, docType, details)`.
- In `QuotationController.js`:
  - Update `sendEmailPrompt(quoteNo)` to call `window.openDocumentEmailModal(quoteNo, 'QUOTATION', quote)`.
- In `ReturnsController.js`:
  - Update `sendEmailPrompt(returnNo)` to call `window.openDocumentEmailModal(returnNo, isSales ? 'SALES_RETURN' : 'PURCHASE_RETURN', returnObj)`.

### Step 3: Upgrade `submitEmailInvoice` and `previewAttachedPdf`
- In `SalesController.submitEmailInvoice`:
  - For `QUOTATION`:
    - Attempts fetch `/api/documents/render?type=QUOTATION&number=${invNo}&format=PDF`.
    - If 400 (v10.0.38 backend pending), generates base64 using `DocumentPdfGenerator.generateQuotationPdf(quoteObj, quoteObj.lines || [], 'base64')`.
  - For `SALES_RETURN` and `PURCHASE_RETURN`:
    - Attempts fetch `/api/documents/render?type=${docTypeParam}&number=${invNo}&format=PDF`.
    - If 400, generates base64 using `DocumentPdfGenerator.generateReturnPdf(retObj, retObj.lines || [], 'base64')`.
  - Dispatches email payload to `OperationsService.sendAuthorityEmail`.
- In `SalesController.previewAttachedPdf`:
  - Fetches server PDF blob, or cleanly falls back to `DocumentPdfGenerator` preview lightbox.

### Step 4: Versioning, Cache Invalidation & Git Deployment
- Bump `version.json` to `10.0.39.02` (Desktop baseline `10.0.39`, Web build `2`).
- Update `js/version.js` to `10.0.39.02`.
- Update `index.html` badges, baseline, menu footer, and all script/link tags to `?v=10.0.39.02`.
- Synchronize copies to `D:\GitHub\ReleaseSource Website\admin` and `D:\GitHub\DSE-ERP-Enterprise\web\admin`.
- Git commit, tag `web-v10.0.39.02`, and push to `origin main --tags`.
