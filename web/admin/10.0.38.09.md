# 10.0.38.09 Production Engineering Specification
## Post-Login Screen Unmasking and Synchronous Auth Dismissal Engine

- **Target Release Version**: `10.0.38.09`
- **Web Build**: `Build #9`
- **Desktop Baseline Alignment**: `10.0.38`
- **Git Release Tag**: `web-v10.0.38.09`
- **Specification Date**: 2026-10-21
- **Status**: Verified & Ready for Production Deployment

### 1. Executive Summary & Problem Diagnosis
In version 10.0.38.08, login submission was successfully stabilized (preventing browser freezes by eliminating recursive MutationObserver DOM wrapping). However, upon successful authentication, users experienced an issue where the auth card cleared or completed verification, but the landing dashboard/workspace did not reveal itself promptly (the auth overlay remained or the application stage was not immediately displayed).

#### Root Causes Identified:
1. **Asynchronous Blocking in `handlePostLoginSuccess`**: Pre-loading steps (such as dashboard controller refresh, company formatting settings, shell polling) were awaiting before or intermixed with DOM unmasking, meaning any slow network call or 403 authorization guard delayed the unmasking of the main application container.
2. **Missing Deterministic CSS Inversion**: While `html.auth-required` set `#auth-overlay { display: flex !important; }` and `#app-container { visibility: hidden !important; }`, there was no explicit inverted rule `html:not(.auth-required) { #auth-overlay { display: none !important; } #app-container { visibility: visible !important; } }`. If any transition or inline display attribute persisted, the screen could fail to unveil immediately.
3. **Role Select Fallback**: When users logged in without explicitly touching the role dropdown, `selectedRole` could be empty or undefined, which caused downstream permission checks to stall.
4. **DatePicker Observer Broad Scoping**: MutationObserver in `DatePickerFormatter.js` was firing `attachAll` on arbitrary DOM mutations without filtering whether date inputs were actually added.

---

### 2. Architectural Changes in 10.0.38.09

#### 2.1 Synchronous Priority Screen Unmasking (`js/app.js`)
In `handlePostLoginSuccess`:
- Removed all blocking operations before unmasking.
- Synchronously and immediately:
  1. Removes `auth-required` class from `document.documentElement` and `document.body`.
  2. Sets `#auth-overlay.style.display = 'none'` and removes `.active`.
  3. Sets `#app-container.style.visibility = 'visible'`.
  4. Calls `window.App.hideAuthOverlay()`.
- Wraps all secondary tasks (audio feedback, toasts, shell counter polling, background data pre-loads) in isolated `try/catch` blocks so background tasks never block UI presentation.

#### 2.2 Deterministic CSS Inversion Rules (`css/app.css` & `index.html`)
Enforced in both `<style>` in `index.html` and `css/app.css`:
```css
html.auth-required #auth-overlay {
  display: flex !important;
  z-index: 999999 !important;
}
html.auth-required #app-container {
  visibility: hidden !important;
}
html:not(.auth-required) #auth-overlay {
  display: none !important;
}
html:not(.auth-required) #app-container {
  visibility: visible !important;
}
```
This guarantees that the moment `auth-required` is removed from `html`, the auth overlay is guaranteed 100% hidden and `#app-container` is guaranteed 100% visible.

#### 2.3 Robust Role Defaulting (`js/app.js`)
Updated `loadLoginRoles`:
- Always defaults `roleSelect.value` to `'ADMIN'` if none selected.
- Avoids inserting a disabled "Select your role" placeholder when valid roles exist.

#### 2.4 Mutation Filtering in DatePickerFormatter (`js/util/DatePickerFormatter.js`)
- Filtered `MutationObserver` records to only execute `attachAll` when an added node is or contains `input[type="date"]`.
- Prevents redundant DOM scans and style recalculations during normal table updates and view navigation.
