## 1. Executive Summary & Problem Analysis

### The Problem
In DSE Web Admin Studio, all data tables format date values strictly according to the enterprise company setting (`company.dateFormat`, e.g. `dd/MM/yyyy`, `dd-MM-yyyy`, `yyyy-MM-dd`, `dd MMM yyyy`) via `FormatUtil.formatDate()`.
However, all 60+ datepickers across the application (filter From/To dates, Invoice Dates, PO Dates, Due Dates, Voucher Dates, etc.) displayed dates formatted according to the browser's operating system regional locale (e.g. `mm/dd/yyyy` on Windows US English machines) rather than the ERP company date format setting.

### Root Cause
1. **HTML5 `<input type="date">` Hardcoded Shadow DOM**:
   The W3C HTML5 specification and browser engines (Chromium/Edge, Safari, Gecko) render native datepickers via an internal C++ Shadow DOM (`::-webkit-datetime-edit`). The segment ordering (month-first vs day-first) and separators are strictly tied to the host OS / browser locale and ignore `placeholder`, CSS, and application JavaScript settings.
2. **Backend API ISO Constraint**:
   Backend Spring Boot controllers and services (`/api/operations/sales/page?from=...`, `ReturnService.java`, `QuotationService.java`, `ReportingService.java`) expect standard ISO dates: `YYYY-MM-DD`. If inputs passed formatted strings like `21/10/2026` directly to APIs, `LocalDate.parse()` would throw `DateTimeParseException`.
3. **Previous Partial Implementation in v10.0.38.02**:
   `DatePickerFormatter.js` previously only set a `placeholder` attribute (which browsers suppress on `input[type="date"]`) and appended a small label badge, leaving the native text untouched.

## 2. Desktop Application First-Principle Inspection

### Desktop Reference: `DatePickerFormatter.java` & `BusinessClock.java`
In the Desktop JavaFX application (`org.example.util.DatePickerFormatter.java`):
1. **StringConverter Decoupling**:
   ```java
   picker.setConverter(new StringConverter<>() {
       @Override
       public String toString(LocalDate date) {
           return date == null ? "" : BusinessClock.formatDate(date);
       }
       @Override
       public LocalDate fromString(String string) {
           return BusinessClock.parseDate(string.trim());
       }
   });
   ```
2. **Editor Synchronization**:
   The visible text in `picker.getEditor()` always shows the formatted date (e.g. `21/10/2026`), while the underlying model value remains a pure `LocalDate`.
3. **Dynamic Settings Listener**:
   When the user changes the Date Format in Settings, `DatePickerFormatter.refreshAll()` updates every active DatePicker's editor text and prompt in real time.

## 3. Web Architecture & Technical Design

To achieve 100% Desktop parity without breaking any existing controller code or backend endpoints:

### A. Dual-Layer Formatted Datepicker Engine
1. **DOM Wrapper (`.dse-datepicker-wrap`)**:
   `DatePickerFormatter.attach(picker)` wraps each `<input type="date">` in a relative inline-flex container that preserves the input's original ID, attributes, classes, and sizing (`width`, `height`, `flex`).
2. **Transparent Native Text + Visible Native Calendar Picker**:
   In `css/app.css`, native datetime text elements (`::-webkit-datetime-edit`, fields, month/day/year) are styled with `color: transparent !important`, while the native calendar icon (`::-webkit-calendar-picker-indicator`) remains visible with `z-index: 3; cursor: pointer;`.
3. **Synchronized Formatted Overlay (`.dse-datepicker-display`)**:
   A lightweight overlay element is positioned directly over the input text box (`left: 12px; top: 50%; transform: translateY(-50%); pointer-events: none; z-index: 2`).
   - When `picker.value` has a date (`2026-10-21`), the overlay renders `FormatUtil.formatDate(picker.value)` (e.g., `21/10/2026` or `21-10-2026`).
   - When `picker.value` is empty, the overlay displays the placeholder prompt (e.g., `dd/mm/yyyy`) with `.is-empty` styling.
4. **Value Interception via Property Descriptor**:
   `Object.defineProperty` intercepts `picker.value` sets in JavaScript (`picker.value = '...'`) to ensure the display overlay immediately reflects the new date even when `change` events are not fired programmatically.
5. **Click & Calendar Interaction**:
   Clicking anywhere on the input opens the native browser calendar popup via `picker.showPicker()`.
6. **Real-Time Dynamic Synchronization**:
   When the user saves a new Date Format in **Settings -> Company Profile**, `FormatUtil.setBusinessPolicy()` fires `dse-date-policy-changed`. `DatePickerFormatter.refreshAll()` refreshes all datepickers across all 38+ screens instantly.

- Overhaul `attach(picker)` to wrap inputs in `.dse-datepicker-wrap` and insert `.dse-datepicker-display`.

- Wire `input`, `change`, and `click` listeners to maintain display synchronization and trigger `showPicker()`.
