## Detailed Investigation & Parity Comparison

### Issue 1: Sale Edit Items Blank & Attachment Download Extension "FILE"

#### A. Sale Edit Items Blank
- **Desktop Architecture (`SalesListController.java` Line 694):**
  ```java
  private void edit(Sales sale) {
      ...
      controller.loadSale(service.getByInvoice(sale.getInvoiceNo()));
      ...
  }
  ```
  Desktop *always* executes `service.getByInvoice(invoiceNo)` to fetch the authoritative `Sales` entity with all associated `sales_line` records before displaying the editor workspace.
- **Current Web Architecture (`SalesController.js` Line 563 & Line 1044):**
  - Line 563 passes `sale` directly from `salesCache` into `openSaleEditorTab(sale, false)`.
  - `salesCache` is populated by `GET /api/operations/sales/page`, which uses `saleSummaryDto` on the server and omits `lines`.
  - Line 1044 checks `if (existingSale && existingSale.lines)`, which evaluates to `undefined`, leaving `this.workspaceItems = []`.
- **Actual Result:** Opening any existing sale in edit mode displays 0 items in the table.
- **Expected Result:** Opening an existing sale in edit mode automatically hydrates all line items, quantities, rates, discounts, GST percentages, and line totals.
- **Resolution:**
  In `SalesController.js` `openSaleEditorTab`:
  ```javascript
  if (existingSale && (!existingSale.lines || existingSale.lines.length === 0) && (existingSale.invoiceNo || existingSale.number)) {
    try {
      const invNo = existingSale.invoiceNo || existingSale.number;
      const fullSale = await window.OperationsService.getSaleByInvoice(invNo);
      if (fullSale && fullSale.invoiceNo) existingSale = fullSale;
    } catch (e) {
      console.warn('Could not hydrate full sale with lines:', e);
    }
  }
  ```

#### B. Attachment Download Extension "FILE"
- **Desktop Architecture (`SupportController.java` Line 31):**
  ```java
  String name = f.fileName() == null ? "attachment" : f.fileName().replace("\"", "_");
  return ResponseEntity.ok()
      .contentType(MediaType.APPLICATION_OCTET_STREAM)
      .header(HttpHeaders.CONTENT_DISPOSITION, "attachment; filename*=UTF-8''" + URLEncoder.encode(name, StandardCharsets.UTF_8).replace("+", "%20"))
      .header("X-Attachment-Name", URLEncoder.encode(name, StandardCharsets.UTF_8))
      .body(f.data());
  ```
  The server explicitly transmits the real filename with its extension in the `Content-Disposition` header and the custom `X-Attachment-Name` header.
- **Current Web Architecture (`ApiService.js` Line 174 & `SalesController.js` Line 3781):**
  - `SalesController.js` passes `const filename = s.attachmentPath.split('/').pop().split('\\').pop() || 'attachment';`. In PostgreSQL, `attachmentPath` is often stored as a token like `FILE`.
  - `ApiService.downloadFile` uses `a.download = filename || 'download'`, completely ignoring the HTTP response headers sent by the server!
- **Actual Result:** File is saved to user's disk as `FILE` without extension; Windows cannot open it.
- **Expected Result:** File is saved with its real extension (`.pdf`, `.png`, `.jpg`, `.xlsx`, etc.) parsed directly from the server's `Content-Disposition` or `X-Attachment-Name` header.
- **Resolution:**
  In `ApiService.js` `downloadFile`:
  Parse `content-disposition` (`filename*=UTF-8''...` or `filename="..."`) and `x-attachment-name`. If filename still lacks extension, sniff magic bytes (`%PDF` -> `.pdf`, `\x89PNG` -> `.png`, etc.) or inspect `Content-Type`.

### Issue 2 & 3: Quotation Screen Not Loading, Buttons Dead, PDF/Excel/Email Errors

- **Desktop Architecture (`QuotationController.java` Lines 1-255 & `QuotationService.java`):**
  Desktop communicates with server controller `QuotationController.java` (`/api/quotations/page`, `/api/quotations/{id}`, `/api/quotations/{id}/lines`, `/api/documents/render?type=QUOTATION&number={no}&format=PDF`).
- **Current Web Architecture (`QuotationController.js` Line 90 & `OperationsService.js`):**
  - `QuotationController.js` calls `window.OperationsService.getQuotationsPage(...)`.
  - In `OperationsService.js`, `getQuotationsPage` was **completely missing**!
  - `window.ApiService.openPdfPreview` was not exported or threw an error.
  - CRUD operations (`getQuotation`, `deleteQuotation`, `markQuotationSent`, etc.) were missing from `OperationsService.js`.
- **Actual Result:** Quotation register throws `TypeError: window.OperationsService.getQuotationsPage is not a function` during `init()`. The page stays stuck on "Loading...", event handlers are unhooked, and all buttons remain dead.
- **Expected Result:** Quotation register loads live quotations, KPIs calculate accurately, table renders with purple Actions dropdowns, PDF preview opens in browser, Excel downloads `.xlsx`, and emails send cleanly.
- **Resolution:**
  1. Add full Quotation REST client to `OperationsService.js`:
     - `getQuotationsPage(...)` -> `/api/quotations/page`
     - `getQuotation(id)` -> `/api/quotations/{id}`
     - `getQuotationByNumber(no)` -> `/api/quotations/by-number?no=...`
     - `getQuotationLines(id)` -> `/api/quotations/{id}/lines`
     - `getQuotationEditorBootstrap(id)` -> `/api/quotations/editor-bootstrap`
     - `createQuotation(data)` -> `POST /api/quotations`
     - `updateQuotation(id, data)` -> `PUT /api/quotations/{id}`
     - `deleteQuotation(id, rowVersion)` -> `DELETE /api/quotations/{id}`
     - `duplicateQuotation(id, user)` -> `POST /api/quotations/{id}/duplicate`
     - `markQuotationSent(id, channel, rowVersion)` -> `POST /api/quotations/{id}/sent`
     - `updateQuotationNotes(id, text, rowVersion)` -> `PUT /api/quotations/{id}/notes`
     - `saveQuotationFollowUp(id, data)` -> `POST /api/quotations/{id}/follow-up`
  2. Implement `openPdfPreview(type, number)` in `ApiService.js` targeting `/api/documents/render?type=${type}&number=${number}&format=PDF` and rendering with proper PDF MIME type.

### Issue 13: Universal Attachment Preview Forces Download Instead of In-Browser Preview

- **Root Cause:**
  When backend serves attachment files via `/api/support/documents/{type}/{id}/attachment-file`, it sets `Content-Type: application/octet-stream` and `Content-Disposition: attachment`. When `ApiService.viewFile` creates a blob without overriding the MIME type, the browser automatically triggers a file download instead of previewing!
- **Actual Result:** Clicking "Preview" downloads the file.
- **Expected Result:** Clicking "Preview" displays the document inline (in a new tab or modal lightbox viewer) for PDFs and images.
- **Resolution:**
  1. In `ApiService.js` `viewFile()`, inspect the filename and magic bytes (`%PDF` -> `application/pdf`, PNG/JPEG -> image). Create `Blob([blobData], { type: resolvedMimeType })`.
  2. When opened, browser's native PDF/image viewer renders the document instead of downloading.
  3. Provide an in-app lightbox modal viewer (`#modal-document-preview`) for instant preview without opening a new window.
