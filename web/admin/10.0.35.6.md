### Issue 1: Saved Reports / Saved View (Tab 3) Showing Blank in Web

#### 1. Desktop Baseline
- **FXML:** `desktop/src/main/resources/fxml/pages/Reports.fxml`
  - Tab 3 is titled `"Saved Reports"` (`tabSavedReports`).
  - Contains `TableView<SavedReportRow> tblSavedReports` with columns: `Name`, `Report Type`, `Saved On`, `Parameters`, `Actions` (`Open`, `Rename`, `Delete`).
  - Top action bar has ComboBox `cmbSavedReports` in report viewer for quick preset loading.
- **Java Controller:** `org.example.controller.ReportsController.java`
  - Method `loadSavedReports()` calls:
    ```java
    supportApi.getSavedViews("REPORT_CENTER");
    ```
  - Parses JSON array of `SavedViewDto(id, name, screen, payload, isDefault, createdAt)`.
  - When selected in viewer, `payload` is parsed to repopulate report type, date range (`from`, `to`), party filter, item filter, and auto-executes `runReport()`.

#### 2. Web Defect Analysis
- In `d:\ERP Website\admin\js\controllers\ReportsController.js` (line 1425):
  ```javascript
  const res = await window.ApiService.get('/api/support/saved-views?screen=REPORT_CENTER');
  ```
- Lines 1433–1460 strictly check if payload starts with `"REPORT_V2:"` or contains pipe-delimited values. If raw JSON or alternative casing is returned, the item is dropped, leaving `allSavedReports = []`.
- When switching to Tab 3 (`switchReportsTab(3)`), `populateViewerSavedDropdown()` is not called, leaving the `<select id="viewer-saved-views">` containing only the default placeholder `<option value="">-- Load Saved Report --</option>`.

#### 3. Root Cause
- Fragile parsing of saved view payload string.
- Dropdown population is not triggered on report viewer load or tab switch.
- Missing default fallback system report presets when user has not saved custom views.

#### 4. Planned Implementation Fix
- In `ReportsController.js`:
  1. Update `loadSavedReports()` to robustly parse payloads (supporting raw JSON, legacy pipe-delimited, and `REPORT_V2:` formats).
  2. If `/api/support/saved-views?screen=REPORT_CENTER` returns an empty array, inject standard default presets (`"Sales Register - This Month"`, `"Purchase Register - This Month"`, `"Stock Summary"`, `"Receivables Aging"`).
  3. Ensure `populateViewerSavedDropdown()` populates both `<select id="viewer-saved-views">` and the Tab 3 catalog table.
  4. On change of `viewer-saved-views`, immediately load parameters and execute report generation.

### Issue 2: Item Master — Import Navigation, Export 500, Concurrency Error

#### 1. Desktop Baseline
- **FXML:** `desktop/src/main/resources/fxml/pages/ItemMaster.fxml`
- **Java Controller:** `org.example.controller.ItemMasterController.java`
  - Toolbar contains: `+ Add Item`, `Import Excel`, `Export Excel`, `Refresh`.
  - `importItemsExcel()` navigates directly to `ImportStudio` with module `Item Master`.
  - `exportItemsExcel()` generates an `.xlsx` workbook using Apache POI `XSSFWorkbook` client-side with 13 columns.
- **Server Enforcement:** `org.example.service.MasterDataService.java`:
  ```java
  assertVersion(d.rowVersion(), e.getRowVersion());
  if (!d.openingStock().equals(e.getOpeningStock())) {
      throw new IllegalArgumentException("Opening stock cannot be modified after creation");
  }
  ```

#### 2. Web Defect Analysis
1. **Import Excel Navigation:**
   - In `index.html` line 3243: `<button class="btn btn-secondary" onclick="window.ItemMasterController.importItemsExcel()">Import Excel</button>`.
   - In `ItemMasterController.js`: Only `importItems()` was defined. Clicking `Import Excel` threw `Uncaught TypeError: window.ItemMasterController.importItemsExcel is not a function`.
2. **Export Excel 500 Error:**
   - In `ItemMasterController.js` line 920: Web called `ApiService.downloadFile('/api/master/items/export/excel', ...)`.
   - The Spring Boot backend does not implement `/api/master/items/export/excel`, returning HTTP 404 or 500.
3. **Edit Item Concurrency Error:**
   - When editing an item, user receives: `"Failed to save item: Item ITEM-0001 was changed by another user. Reload the latest version before saving again."`.
   - In `ItemMasterController.js`, `editingRowVersion` was read from stale cached data (`MasterService.getItems()` cached for 5 minutes).
   - Furthermore, `input-opening-stock` remained editable for existing items, violating backend immutability rules.

#### 3. Planned Implementation Fix
- In `ItemMasterController.js` and `index.html`:
  1. Define `importItemsExcel()`:
     ```javascript
     function importItemsExcel() {
       if (window.NavigationRouter) window.NavigationRouter.selectNav('view-import');
       if (window.ImportController) window.ImportController.selectModule('Item Master');
     }
     ```
  2. Implement client-side XLSX export via SheetJS (`window.XLSX`) with 13 standard columns matching Desktop.
  3. When opening the Edit Item modal:
     - Fetch fresh item DTO via `window.ApiService.get('/api/master/items/' + id)` to obtain the exact `rowVersion`.
     - Disable `input-opening-stock` for existing items (read-only with badge `"Opening stock locked"`).
     - On concurrency error, prompt the user with auto-reload option.

    - Bank Withdrawal voucher type: `'BANK WITHDRAWAL'`
    - Expense voucher type: `'EXPENSE'`

#### 2. Web Defect Analysis
- In `d:\ERP Website\admin\js\controllers\FinanceController.js` (line 248):
  ```javascript
  const isBank = currentSubView === 'bank';
  entries = allVouchers.filter(v => {
    return isBank
      ? (v.voucherType === 'RECEIPT' || v.voucherType === 'PAYMENT' || v.voucherType?.includes('CONTRA'))
      : (v.voucherType === 'EXPENSE' || v.voucherType === 'PAYMENT');
  });
  ```

- The web UI lacked the left-side docked entry form panel, showing only an empty table and a modal button.
- Account and payment mode dropdowns had hardcoded mock values.

#### 3. Planned Implementation Fix
- In `FinanceController.js`:

     ```javascript
     const isBank = currentSubView === 'bank';
     entries = allVouchers.filter(v => {
       const t = (v.voucherType || '').toUpperCase();
       return isBank
         ? (t.includes('BANK') || t.includes('DEPOSIT') || t.includes('WITHDRAWAL') || t === 'RECEIPT' || t === 'CONTRA')
         : (t.includes('EXPENSE'));
     });
     ```
  2. Implement the side-by-side workspace with docked `entryFormPanel` matching `BankExpense.fxml`.
