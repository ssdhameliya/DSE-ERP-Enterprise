## 2. In-Depth Root Cause Analysis & Technical Solutions

### Issue 1A: Date Pickers & Dropdown Selections Ignore Company Setting Date Format
- **Desktop Logic (`DatePickerFormatter.java` & `BusinessClock.java`)**:
  - In Desktop, all date pickers are attached to `DatePickerFormatter.attach(picker)`:
    ```java
    picker.setConverter(new StringConverter<>() {
        @Override public String toString(LocalDate date) {
            return date == null ? "" : BusinessClock.formatDate(date);
        }
        @Override public LocalDate fromString(String string) {
            return BusinessClock.parseDate(string.trim());
        }
    });
    ```
  - Prompt text dynamically displays the format pattern (`dd/MM/yyyy`, `dd-MM-yyyy`, `yyyy-MM-dd`). On commit or focus loss, the input parses strictly according to `BusinessClock.datePattern()`.
- **Current Web Defect**:
  - The Web interface uses native HTML5 `<input type="date">` across 49 fields.
  - Per HTML5 specification, `<input type="date">` **always renders according to the browser's host OS regional settings**, ignoring application stylesheets and JavaScript `FormatUtil._dateFormat`.
- **Planned Web Fix**:
  - Implement an enterprise `DatePickerFormatter.js` module in `js/util/DatePickerFormatter.js`.
  - Attach an interactive date input formatter that:
    1. Displays a high-contrast badge or formatted overlay showing the date in the configured `FormatUtil._dateFormat`.
    2. Dynamically updates placeholder/prompt text on `dse-date-policy-changed` events.
    3. Guarantees the underlying `.value` remains strictly ISO-8601 (`YYYY-MM-DD`) so backend query parameters (`from`, `to`, `invoiceDate`) never break.

### Issue 1B: Universal Preview & Export Downloads Files Without Extension (`.FILE`)
- **Desktop Logic**:
  - Desktop uses JavaFX `FileChooser` with explicit extension filters:
    `chooser.getExtensionFilters().add(new FileChooser.ExtensionFilter("Excel Spreadsheet (*.xlsx)", "*.xlsx"));`
  - Filenames always end with `.xlsx`, `.pdf`, or `.csv`.
- **Current Web Defect (`ApiService.js` lines 331–335)**:
  - In `ApiService.js`:
    ```javascript
    if (dlBtn) {
      dlBtn.href = blobUrl;
      const downloadName = (title || 'preview_document').replace(/[^a-zA-Z0-9._-]/g, '_');
      dlBtn.setAttribute('download', downloadName);
    }
    ```
  - When callers invoke `viewFile(endpoint, "Sales_Register_Excel")` or `viewDocumentPdf(type, number)` with `title = "${type} ${number} PDF"`, `title` has **no file extension**.
  - In line 354: `<a href="${blobUrl}" download="document" ...>` also has no extension.
  - Windows browsers download the file as `Sales_Register_Excel` without `.xlsx` or `.pdf`. Windows file manager then classifies it as `Type: File` (`.FILE`), preventing users from opening it by double-clicking.
- **Planned Web Fix**:
  - In `ApiService.js`, enhance `showUniversalPreviewModal` and `downloadFile` to enforce extensions based on MIME type and magic bytes:
    ```javascript
    function ensureExtension(filename, mime) {
      if (!filename) filename = 'document';
      const lower = filename.toLowerCase();
      if (lower.endsWith('.pdf') || lower.endsWith('.xlsx') || lower.endsWith('.csv') || lower.endsWith('.png') || lower.endsWith('.jpg')) {
        return filename;
      }
      if (mime === 'application/pdf') return filename + '.pdf';
      if (mime === 'application/vnd.openxmlformats-officedocument.spreadsheetml.sheet' || mime === 'application/vnd.ms-excel') return filename + '.xlsx';
      if (mime === 'text/csv') return filename + '.csv';
      return filename + '.pdf';
    }
    ```
  - Inspect magic bytes in `viewFile` for Zip/XLSX (`0x50, 0x4B, 0x03, 0x04`) in addition to PDF and images.

### Issue 2: Post-Login State Mismatch vs. Refresh & Header Badges Showing 0
- **Desktop Logic (`DashboardHomeController.java` & `Dashboard.fxml`)**:
  - On launch or login, Desktop immediately reads cached badge totals, fires `/api/insights/shell-counts`, and displays live numbers in the navigation badges.
- **Current Web Defect (`index.html`, `app.js`, `NavigationRouter.js`)**:
  1. In `index.html`, header badges (`#badge-reminders`, `#badge-notifications`, `#badge-email`, `#badge-whatsapp`) are hardcoded with `0`.
  2. In `app.js` line 564, `handlePostLoginSuccess` calls:
     `window.NavigationRouter.selectNav('view-dashboard');`
     In `NavigationRouter.js` line 120:
     ```javascript
     if (currentViewId === viewId && document.getElementById(viewId)?.classList.contains('active')) {
       return; // EARLY EXIT!
     }
     ```
     Because `currentViewId` initializes to `'view-dashboard'`, and `<div id="view-dashboard" class="module-view active">` in `index.html` already has class `active`, `selectNav` **immediately returns** and **does not run** `dispatchLifecycle('view-dashboard')`!
  3. Furthermore, `pollShellCounts()` in `handlePostLoginSuccess` was placed after several sequential async awaits (`FormatUtil.setBusinessPolicy`, `DashboardController.refresh`, `ItemMasterController.loadItems`, `PartyController.loadCustomers`).
  4. On page refresh (F5), `App.init()` booted with `isAuthenticated() = true`, eagerly calling `pollShellCounts()` before view dispatch, creating a stark visual discrepancy between fresh login and refresh.
- **Planned Web Fix**:
  - Cache shell counts in `localStorage` under `dse_shell_counts` so badges render real numbers immediately upon login card submission.
  - In `handlePostLoginSuccess`, run `pollShellCounts()` concurrently with view initialization.
  - Pass a `forceLifecycle = true` flag to `selectNav` so the post-login landing view is always mounted and refreshed.

### Issue 3: Remember Me Checkbox Not Working or Clearing
- **Desktop Logic (`LoginController.java` lines 197–198, 906–952)**:
  - Desktop attaches a listener directly to the checkbox:
    ```java
    chkRemember.selectedProperty().addListener((obs, oldValue, selected) -> {
        if (!selected) clearRememberedLogin();
    });
    ```
  - When restored, `restoreRememberedLogin()` reads `PREFS.getBoolean(PREF_REMEMBER, false)`. If false, `chkRemember.setSelected(false)` and nothing is auto-filled.
- **Current Web Defect**:
  1. In `index.html` line 262: `<input type="checkbox" id="login-remember" checked ...>` was hardcoded with `checked`.
  2. In `app.js` line 106: `rememberCheck.checked = savedRemember || !!savedIdentity` forced the checkbox to `checked` whenever an identity string existed in `localStorage`, overriding explicit user unchecking.
  3. No `change` event listener existed on `#login-remember` to immediately wipe credentials when unchecked.
- **Planned Web Fix**:
  - Remove hardcoded `checked` attribute from `index.html`.
  - Read `localStorage.getItem('dse_remember_me') === 'true'`. If false, leave the checkbox unchecked and do NOT populate `login-identity`.
  - Add `change` listener on `#login-remember`: when unchecked by the user, immediately purge `dse_remember_me`, `dse_saved_identity`, and `dse_saved_role`.

### Issue 4: Quotation View PDF/Excel Canonical Error & Email Failure
- **Desktop Logic (`QuotationController.java` lines 87–145)**:
  - Quotation PDF preview and download call `ManagedInvoicePdfService.quotation(q.no.get())` (client Document Studio generator).
  - Quotation Excel export calls `ExcelOutputService.generate(...)` locally.
  - Desktop **never calls** `/api/documents/render?type=QUOTATION`.
- **Current Web Defect**:
  - `QuotationController.js` lines 509 & 522 called `/api/documents/render?type=QUOTATION...`.
  - In server `CanonicalDocumentService.java` lines 253–258:
    ```java
    return switch (n) {
        case "SALE", "SALES", "SALES_INVOICE" -> DocumentType.SALES_INVOICE;
        case "PURCHASE", "PURCHASES", "PURCHASE_INVOICE" -> DocumentType.PURCHASE_INVOICE;
        default -> throw new IllegalArgumentException(
                "Canonical output is currently supported for Sales Invoice and Purchase Invoice.");
    };
    ```
  - The server strictly rejects `QUOTATION`, throwing 400.
  - In `downloadExcel`, the server call failed with an error toast *before* the SheetJS fallback ran, confusing the user.
  - In `sendEmailPrompt`, `attachmentBase64` was passed as `null`. When SMTP is unconfigured or encounters connection errors, `SmtpMailService` throws `EmailDeliveryException.business`:
    `"Email delivery is temporarily unavailable. Please contact your administrator or try again later."`
- **Planned Web Fix**:
  - In `QuotationController.js`, remove calls to `/api/documents/render?type=QUOTATION`.
  - Route PDF preview and download directly through client-side Document Studio / jsPDF rendering.
  - In `downloadExcel`, invoke the authoritative SheetJS generator directly without making an invalid server request.
  - In `sendEmailPrompt`, render the quotation PDF into a Base64 string before calling `/api/authority/email`, and surface clear SMTP configuration diagnostics if the server mailer is disabled.

### Issue 5: Universal Print Engine Generates Blank Page (`Jasvi Industries ERP — Centralized Enterprise Studio.pdf`)
- **Desktop Logic**:
  - Desktop prints directly to the operating system print spooler via JavaFX / Jasper Print APIs, streaming styled vector documents.
- **Current Web Defect (`css/app.css` line 493 & line 1364)**:
  - In `css/app.css` line 492:
    ```css
    @media print {
      body * { visibility: hidden; }
      #printable-barcode-area, #printable-barcode-area * { visibility: visible; }
    }
    ```
  - And in line 1364:
    ```css
    @media print {
      body * { visibility: hidden !important; }
      #printable-invoice-modal, #printable-invoice-modal * { visibility: visible !important; }
    }
    ```
  - Because of `body * { visibility: hidden !important; }`, **every single element on the web page is completely hidden** during `window.print()`, unless `#printable-invoice-modal` or `#printable-barcode-area` happens to be active.
  - Printing from Sales Register, Purchase Register, Quotations, Returns, Reports, or 360 screens prints an empty white sheet with the HTML title `Jasvi Industries ERP — Centralized Enterprise Studio.pdf`.
- **Planned Web Fix**:
  - Replace the destructive `body * { visibility: hidden !important; }` rules in `css/app.css`.
  - Specifically target and hide only application chrome:
    ```css
    @media print {
      header.app-header,
      aside.app-sidebar,
      .workspace-tabs,
      .view-actions,
      .filter-bar,
      .pagination-container,
      .side-drawer,
      #auth-overlay,
      .modal:not(#printable-invoice-modal) {
        display: none !important;
      }
      .module-view.active,
      .module-view.active * {
        visibility: visible !important;
      }
    }
    ```
  - Now, any register or document printed via `window.print()` outputs the full, readable high-contrast table.

### Issue 6: PDF Generation Dates Not Following Setting Date Format
- **Desktop Logic (`TaxInvoicePdfGenerator.java` line 1346)**:
  - Calls `BusinessClock.formatDate(LocalDate)` which formats using `company.dateFormat`.
- **Current Web Defect**:
  - Server-side `org.example.server.util.BusinessClock.java` lines 65–70 reads `company.dateFormat` from `ConfigManager.get("company.dateFormat")` or `DSE_BUSINESS_CONFIG_FILE`. In a server runtime, this file does not exist, so it defaults to `"dd/MM/yyyy"`. It never reads from PostgreSQL `application_setting` table where Web saves settings.
  - On the client side, `SalesController.js` lines 2733 & 2819 called `this.buildSalesInvoiceJsPdf(saleObj)`. This function was **never defined**, causing jsPDF generation to crash with `TypeError: this.buildSalesInvoiceJsPdf is not a function`.
- **Planned Web Fix**:
  - Implement `buildSalesInvoiceJsPdf(saleObj)` in `SalesController.js` and `InvoicePdfService.js` strictly using `FormatUtil.formatDate(date, FormatUtil._dateFormat)`.
  - Pass the active `dateFormat` as a query parameter (`&dateFormat=...`) when requesting server document rendering so the backend generator respects the client's configured format.

### Issue 9: Logo / Settings Synchronization & REST API Direct Migration
- **Desktop Logic (`BrandingService.java` & `ServerResourceRepository.java`)**:
  - Assets (`company.logoPath`, `company.signaturePath`, `payment.qrImagePath`, `application.brandImagePath`, `application.markImagePath`) are stored as binary records in database table `server_resource` and served via `/api/authority/resources/BUSINESS_ASSET/{key}`.
- **Current Web Defect**:
  1. `BrandingService.js` line 174 aborted `refreshRemote()` if unauthenticated, preventing login screen logo updates.
  2. In `SettingsController.js` line 106, if an asset value was empty or deleted in Desktop, `resolveAssetUrl` fell back to `'server-resource:' + assetKey`, causing stale or deleted images to keep displaying.
  3. Web stored local `blob:http://...` object URLs in `localStorage` under `dse_brand_banner_url` and `dse_brand_mark_url`.
- **Architectural Response to User's REST API Question**:
  - **Yes, absolutely!** All buttons and branding in both Desktop and Web can and should operate directly on PostgreSQL database records via the unified REST API:
    - `GET /api/authority/resources/BUSINESS_ASSET/{key}` (retrieves binary image from database table `server_resource`).
    - `POST /api/authority/resources/BUSINESS_ASSET/{key}` (uploads binary image directly to database).
    - `DELETE /api/authority/resources/BUSINESS_ASSET/{key}` (deletes binary image from database).
    - `GET /api/support/settings/public` (returns public branding for login screen before authentication).
  - When an asset is deleted from either Desktop or Web, it is removed from `server_resource` and `application_setting` in PostgreSQL. When Web requests the deleted resource, it receives a 404, immediately removing the image on Web without requiring manual localStorage clearing.

### Issue 10: Dynamic KPI Layout (Single Ribbon, Never Wrap Down)
- **Desktop Logic (`ResponsiveKpiLayoutManager.java` lines 28–180)**:
  - Enforces a single row:
    `Cards always stay in one row; density is selected from the real usable pixels per visible card rather than from card count alone.`
  - Dynamic density thresholds: `COMPACT_CARD_THRESHOLD = 225.0`, `DENSE_CARD_THRESHOLD = 170.0`.
  - All cards forced to `flex: 1 1 0 !important; min-width: 0 !important;` with `flex-wrap: nowrap !important;`.
- **Current Web Defect**:
  - Certain views (e.g. `.dash-kpi-row-6`) used wrapping or grid auto-fit. When screen width is constrained or more cards are present, cards wrap down to a second row, doubling vertical height and pushing the table down.
- **Planned Web Fix**:
  - Apply `.erp-kpi-ribbon-dynamic` across all KPI sections:
    ```css
    .erp-kpi-ribbon-dynamic {
      display: flex !important;
      flex-wrap: nowrap !important;
      gap: 8px !important;
      width: 100% !important;
      align-items: stretch !important;
      overflow-x: auto;
    }
    .erp-kpi-ribbon-dynamic .kpi-card {
      flex: 1 1 0 !important;
      min-width: 0 !important;
    }
    ```
  - Implement a `ResizeObserver` that automatically toggles `.kpi-compact` and `.kpi-dense` classes based on card width, ensuring cards never wrap down.

### Issue 12: Table Vertical Scrolling Locked / Unreachable Records
- **Desktop Logic**:
  - Desktop `TableView` uses a VirtualFlow where the scrollbar independently controls row virtualization.
- **Current Web Defect (`css/app.css` line 930 & lines 1537–1544)**:
  1. In `css/app.css` line 930:
     ```css
     .sales-table-scroll, .table-responsive, .data-table-wrap, .table-scroll {
       overflow-x: auto !important;
       max-height: calc(100vh - 420px);
       min-height: 380px;
       width: 100%;
     }
     ```
     `overflow-y: auto !important;` was completely omitted!
  2. In `css/app.css` line 1537:
     ```css
     .register-table-panel, .sales-table-panel {
       flex: 1;
       min-width: 0;
       display: flex;
       flex-direction: column;
     }
     ```
     Missing `min-height: 0;`! Under CSS Flexbox rules, a flex container defaults to `min-height: auto`. When child content is taller than the screen, the container stretches infinitely instead of shrinking to the viewport. The table scrollbar never activates, and bottom rows overflow off the bottom edge of the screen, permanently unreachable.
- **Planned Web Fix**:
  - Add `min-height: 0 !important;` to `.register-split-container`, `.register-table-panel`, `.sales-table-panel`, and `.register-content-area`.
  - Ensure `.sales-table-scroll`, `.table-scroll`, and `.table-responsive` declare `overflow-y: auto !important; overflow-x: auto !important; flex: 1 !important; min-height: 0 !important;`.
