## 1. Executive Summary & Desktop Architecture Investigation (Rules 1 & 3)

In Desktop ERP (`desktop/src/main/java/org/example/util/DynamicTableLayoutManager.java`, `RegisterUiSupport.java`, and `RegisterDetailDrawer.java`), all tables operate under the **`TableView.CONSTRAINED_RESIZE_POLICY_FLEX_LAST_COLUMN`** dynamic layout authority.

### Desktop Dynamic Table Engine Highlights:
1. **Zero Horizontal Scrolling**: Under no circumstance does a register table show a horizontal scrollbar or force right-to-left scrolling when a side panel opens.
2. **Dynamic Header & Column Compression (`allocateDense`)**:
   - When the side panel opens, the available container width drops (e.g. from 1250px down to ~850px).
   - Desktop dynamically tests whether normal readable floors fit: `floorTotal <= available`.
   - If `floorTotal > available` (the side panel opened), Desktop switches into **`allocateDense(columns, profiles, available)`**.
   - In `allocateDense`, column floors drop to compact readable limits:
     - Checkbox / Select: `36px`
     - Actions Menu: `96px` (hard floor `78px`, reducible to `72px`)
     - Long Text (Customer / Supplier / Item / Description): `66px` (flex weight `3.0`)
     - Status / Document Status: `58px`
     - Invoice / Reference / Document: `56px`
     - Amount / Total / Balance / Paid: `52px`
     - Date / Due Date / Contact / Unit / Quantity / GSTIN: `44px`
   - For a 12-to-14 column table, the total dense floor is only **~580px to 680px**.
   - Since available width beside a 380px drawer is typically **820px to 950px**, the table fits effortlessly (`total <= available`).
   - The remaining extra width (e.g. `850px - 620px = 230px`) is proportionally allocated to columns based on flex weights (with the primary customer/description column receiving the highest weight `3.0`).
   - Any residual pixel rounding is closed into the flex column via `closeResidual(widths, available)`.
   - All 12 to 14 headers stay fully visible, headers wrap cleanly across 2 lines on word boundaries, cell contents ellipsize with native HTML tooltips on hover, and the table width remains **100% of the available viewport** without horizontal scrolling.

## 4. Root Cause Analysis of Web Horizontal Scroll

### Root Cause 1: The `floorTotal` Constrained Assignment Bug
In `d:\ERP Website\admin\js\util\DynamicTableLayoutManager.js` lines 334–337:
```javascript
// BUGGY EXISTING CODE:
const isConstrained = floorTotal > available;
const effectiveAvailable = isConstrained ? floorTotal : available;
table.style.width = isConstrained ? (floorTotal + 'px') : '100%';
table.style.minWidth = isConstrained ? (floorTotal + 'px') : '100%';
```
When a side drawer opens, `available` drops to ~850px. Because `floorTotal` was calculated as ~1440px:
1. `isConstrained` evaluates to `true`.
2. The table width is explicitly hardcoded to **`1440px`** in inline styles!
3. The table container is forced to sprout a horizontal scrollbar.
4. The user cannot see all 12 headers and is forced to scroll back and forth from right to left!

### Root Cause 2: Failure to Call `allocateDense()` in `layoutNow()`
In `DynamicTableLayoutManager.js` lines 339–341:
```javascript
// BUGGY EXISTING CODE:
// Allocate widths
const widths = allocateFromFloors(profiles, effectiveAvailable, floorTotal, weightTotal);
closeResidual(widths, effectiveAvailable, profiles);
```
Even though `allocateDense` was written as a helper function, it was **never called**! The code always called `allocateFromFloors` using `effectiveAvailable = floorTotal`. It completely omitted the dense compression logic that Desktop uses to squeeze all headers into available space.

### Root Cause 3: Broken Function Call in `RegisterUiSupport.js`
In `js/util/RegisterUiSupport.js` lines 87–89:
```javascript
if (window.DynamicTableLayoutManager && window.DynamicTableLayoutManager.reflowAllTables) {
  window.DynamicTableLayoutManager.reflowAllTables();
}
```
In `DynamicTableLayoutManager.js`, the method was named `requestLayoutIn()` instead of `reflowAllTables()`. As a result, this check silently failed every single time a drawer opened or closed, leaving the table in its pre-drawer unadjusted layout.

## 5. Technical Implementation Plan

### Step 1: Complete Rewrite of `DynamicTableLayoutManager.js`
1. **Desktop Mathematical Parity**:
   - Replicate `DynamicTableLayoutManager.java:234-237`:
     ```javascript
     const widths = floorTotal <= available
       ? allocateFromFloors(profiles, available, floorTotal, weightTotal)
       : allocateDense(profiles, available);
     closeResidual(widths, available, profiles);
     ```
   - Lock table width strictly:
     ```javascript
     table.style.tableLayout = 'fixed';
     table.style.width = '100%';
     table.style.minWidth = '0';
     ```
   - Ensure the scroll container has `overflow-x: hidden !important;` for dynamic tables.
2. **Compact Floor Constants**:
   - Implement Desktop's exact `denseFloor`:
     - Long Text: `66px`
     - Status / Document Status: `58px`
     - Invoice / Reference / Document: `56px`
     - Amount / Total / Balance / Paid: `52px`
     - Checkbox: `36px`
     - Actions: `96px` (hard floor `76px`)
     - Default / Other: `44px`
3. **Word-Boundary Header Wrapping**:
   - Headers wrap cleanly across 2 lines without clipping text or breaking words awkwardly.
   - Text cells ellipsize with native `title` attribute for full content preview on hover.
4. **Public API Exposal**:
   - Expose `reflowAllTables(root)` as an alias to `requestLayoutIn(root)`.

### Step 2: Update `RegisterUiSupport.js`
- Connect `showDrawer()` and `hideDrawer()` directly to `window.DynamicTableLayoutManager.requestLayoutIn(document)` with a secondary 50ms pulse for smooth CSS animation completion.

### Step 3: Controller Integration
- Ensure all 22 controllers that toggle a side panel call `DynamicTableLayoutManager.requestLayout(table)` upon drawer open and close.
- In `SalesController.js`, update `openInvoiceDrawer()` and `closeInvoiceDrawer()` to invoke dynamic layout.

### Step 4: CSS Styling Adjustments in `css/app.css`
- Ensure `.register-table-panel`, `.standard-table-card`, and `.sales-desktop-table` do not force fixed horizontal min-widths when docked beside `.slide-detail-drawer` or `.sales-inline-drawer`.

### Step 5: Version Registry & Cache Busters (Rule 7)
- Bump version to **`10.0.38.04`** (Web Build #4).
- Update `version.json`, `js/version.js`, and `index.html` cache busters (`?v=10.0.38.04a`).
