## 1. Executive Summary

This release resolves two critical UI/UX defects reported by the user, provides complete root cause analysis without assumptions, fixes an architectural table collapse bug across the ERP, and establishes a permanent single-file version automation system:

1. **Login Page Refresh Visual Flash (Root Cause & Permanent Zero-Flicker Fix)**:
   - Eliminates the 500ms–1000ms "Flash of Stale Static Markup" where the login screen rendered an outdated version badge (`10.0.41.09`), a white rectangular corporate banner, legacy purple buttons, and plain labels before abruptly snapping into the current UI.
   - Proves definitively that "Remember Me" is not the cause, and synchronizes `index.html` static markup and `<head>` execution to deliver instantaneous Frame-0 rendering identical to post-initialization state.

   - Re-architected `item-master.html` and `inventory.html` to standard horizontal docked split-pane, allowing the table to remain 100% visible, active, and dynamically resized alongside the side panel.
3. **Automated Single-File Version Synchronization**:
   - Replaced manual 67-line version updating across `version.json`, `js/version.js`, and `index.html` with a single-source-of-truth automation tool (`scripts/sync-version.ps1` and `scripts/sync-version.py`).
   - Editing `version.json` (or running `.\scripts\sync-version.ps1 -Bump`) automatically synchronizes `version.json`, `js/version.js`, static version badges, and all 64+ cache-busting query strings in `index.html` with 0 human error.

## 2. Issue 1: Login Page Visual Flash on Refresh (Root Cause Analysis)

### 2.1 The Symptom (Observed in User Screenshots 1 & 2)
When the user refreshed `https://erp-uat.jasviindustries.in/#dashboard`:
- **First 500ms – 1s (Image 1)**:
  - White rectangular banner image with company logo, ISO text, phone, and email was visible.
  - Small square logo mark box was visible below it.
  - Tagline was `"Enterprise Production & Distribution"`.
  - Version badge displayed `"Version 10.0.41.09"`.
  - Buttons were styled in legacy purple (`auth-btn-purple`).
  - Form labels were plain text without 3D badges.
  - "Remember Me" checkbox was unchecked.
- **After 1s (Image 2)**:
  - White banner and mark box vanished completely.
  - Tagline snapped to `"Excellence in Ceramic Manufacturing & Enterprise Engineering"`.
  - Version badge snapped to `"Version 10.0.41.10"` (or `.11`).
  - Buttons snapped to Emerald Green 3D gradients (`.role-save` / `.role-add`).
  - Form labels received cyan, orange, green, and tactile `📌` badges.
  - "Remember Me" checkbox checked itself and credentials appeared.

### 2.2 Is it because of the "Remember Me" button?
**NO.** "Remember Me" only reads and writes `dse_remember_me` and `dse_saved_identity` in `localStorage`. It has no impact on banner visibility, tagline text, version badges, or button gradients.

### 2.3 The Actual Root Cause: Dual-State Asynchronous DOM Mutation (FOSM)
The defect was caused by a fundamental mismatch between the raw static HTML in `index.html` and the client JavaScript:
1. **Static HTML Stale Baseline**:
   - In `index.html` lines 281–297:
     ```html
     <div class="auth-brand-banner-box" id="auth-brand-banner-box">
       <img src="assets/brand-banner.png" alt="Jasvi Industries" ...>
     </div>
     <div class="auth-brand-mark-box" id="auth-brand-mark-box">
       <img src="assets/brand-mark.png" alt="Jasvi Mark" ...>
     </div>
     <div class="auth-brand-subtitle">Enterprise Production &amp; Distribution</div>
     <span class="auth-brand-version-badge" id="auth-app-version-badge">Version 10.0.41.09</span>
     <button type="submit" id="btn-login-submit" class="auth-btn-purple">
     ```
   - When the user refreshes, the browser paints Frame 0 immediately from this raw HTML.
2. **Asynchronous JavaScript Overwrite**:
   - 500ms later, after network transfers and DOM parsing:
     - `BrandingService.js`: Fetches public settings or reads `dse_branding` from `localStorage`. Finding no active banner image URL, it executes `bannerBox.style.display = 'none'` and updates the subtitle.
     - `version.js`: Executes `syncVersionToDOM()` on `DOMContentLoaded`, replacing the text with the current version.
     - `ButtonIconEnhancer.js`: Runs on `DOMContentLoaded`, matches "LOGIN" to `role-save`, and replaces `auth-btn-purple` with `.btn-action-3d .role-save` (Emerald Green).
     - `LabelIconEnhancer.js`: Runs on `DOMContentLoaded`, injecting badge spans.
     - `app.js`: Restores `dse_remember_me` checkbox state.
3. Because all 6 visual properties differed between static HTML and runtime JavaScript, the screen flashed dramatically.

### 2.4 Resolution
- **Static HTML Alignment**: Update `index.html` so that Frame 0 matches Frame 1 out-of-the-box:
  - Hide `#auth-brand-banner-box` and `#auth-brand-mark-box` by default (`display: none;`).
  - Set default subtitle to `"Excellence in Ceramic Manufacturing & Enterprise Engineering"`.
  - Set version badge to `"Version 10.0.41.12"`.
  - Set button classes directly to `.auth-btn-purple.role-save.btn-action-3d` and `.auth-btn-purple-outline.role-add.btn-action-3d`.
- **Pre-Paint Head Script**: Add a synchronous micro-script in `<head>` that reads `localStorage.getItem('dse_branding')` and `localStorage.getItem('dse_remember_me')` before the `<body>` is painted, guaranteeing 0ms visual divergence.

## 3. Issue 2: Item Master Table Disappearance & All-Table Audit

### 3.1 The Symptom (Observed in User Screenshots 3 & 4)
- When viewing Item Master (`views/item-master.html`), the table displays all 8 items properly.
- Upon clicking any record (e.g., `ITEM-0001`), the entire table disappears!
- Only the item detail card appears on the left; the entire center and right of the screen becomes an empty dark void.

### 3.2 Root Cause Analysis
- In `views/item-master.html` line 71:
  ```html
  <div class="register-workspace" id="item-master-workspace" style="flex:1; min-height:0; display:flex; flex-direction:column;">
  ```
- `.register-workspace` is defined in `css/app.css` line 1941 as a horizontal flex container (`display: flex; gap: 14px;` row layout).
- The inline style `flex-direction: column` converted the workspace into a vertical top-to-bottom stack.
- The workspace contains two children:
  1. `.sales-table-card` (`flex: 1; min-height: 0;`)
  2. `#item-detail-drawer` (`flex-shrink: 0 !important; width: 380px !important; max-height: calc(100vh - 270px) !important;`)
- When `#item-detail-drawer` is hidden (`display: none`), the table card expands to fill the container.
- When the user clicks a row, `RegisterUiSupport.showDrawer('item-detail-drawer')` makes the drawer visible (`display: flex`).
- Because of `flex-direction: column` and the drawer's `flex-shrink: 0`, the drawer consumed the available vertical height, **crushing `.sales-table-card` (which had `min-height: 0`) down to 0px height**!
- The drawer then occupied the top-left (380px wide), leaving the entire remainder of the horizontal viewport blank.

- Both views now dock their drawer on the right with full side-by-side visibility and automatic `DynamicTableLayoutManager` column recalculation.

## 4. Issue 3: Automated Single-File Version Synchronization

### 4.1 Problem
Every release required manually updating ~67 individual lines:
- `version.json` (3 occurrences)
- `js/version.js` (3 occurrences)
- `index.html` (1 version badge, 1 baseline label, 64 `<link>` / `<script>` cache-busting query params)
Missing even one line (as happened with line 294 in `index.html`) causes stale display and user confusion.

### 4.2 Solution: Single Source of Truth Automation
1. **Single File Authority**: `version.json` is declared the sole authoritative version file.
2. **Scripts Created**:
   - `scripts/sync-version.ps1` (PowerShell)
   - `scripts/sync-version.py` (Python 3.14)
3. **Capabilities**:
   - **Manual Mode**: Edit `version.json`, then run `.\scripts\sync-version.ps1` or `python scripts/sync-version.py`.
   - **Automated Bump Mode**: Run `.\scripts\sync-version.ps1 -Bump -Summary "Release details..."` to automatically increment the build number, format timestamps, regenerate `js/version.js`, update line 294 in `index.html`, and replace all 64+ `?v=...` occurrences in 80 milliseconds.
