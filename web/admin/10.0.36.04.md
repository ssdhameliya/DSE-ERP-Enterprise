## 1. Executive Summary & Defect Root Cause Analysis

Following production release `10.0.36.03`, deep investigation was conducted against Desktop source code (`D:\GitHub\DSE-ERP-Primary`), current Web code (`d:\ERP Website\admin`), and the user-provided screenshots. Nine major systemic defects were audited and isolated:

### 1. Date Format & Timezone Propagation
- **Footer & Header Clocks**: `app.js` (lines 6–29) and `BrandingService.js` (lines 184–203) maintained hardcoded interval loops with hardcoded `'IST'` and hardcoded `'en-GB'` day/month strings, completely ignoring user settings in `FormatUtil`.
- **Controllers Bypassing FormatUtil**: 8 controllers (`AutomationCenterController.js`, `BankStatementController.js`, `CommunicationController.js`, `CreditDebitNoteController.js`, `PurchaseReconController.js`, `RecordPaymentController.js`, `ReminderCenterController.js`, and `ReturnsController.js`) had local `formatDate` helper functions hardcoding `dd/mm/yyyy` or `toLocaleDateString()`, preventing updated settings from reflecting in their tables.
- **Settings Event Broadcast**: Saving Settings updated localStorage and memory in `FormatUtil`, but never dispatched a reactive update event or refreshed the clock/open tables.

### 2. Branding & Logo/Mark Synchronization
- In Desktop (`BrandingService.java` & `LoginController.java:217-240`), there are three distinct asset keys:
  - `application.brandImagePath`: Wide banner logo ("JASVI INDUSTRIES" header).
  - `application.markImagePath`: Square application mark card ("J" logo above "Jasvi Creation").
  - `company.logoPath`: Document/invoice header logo.
- In Desktop, if `application.markImagePath` is empty or removed, `LoginController.showApplicationMark(null)` explicitly sets `brandMarkBox.setVisible(false)` and `brandMarkBox.setManaged(false)`.
- In Web, `index.html` has a static, hardcoded `<div id="auth-brand-mark-box"><img src="assets/brand-mark.png"></div>` that was **never hidden** when the asset was removed on the server. Furthermore, Web Settings never synchronized cleared assets to the login startup elements.

### 3. Reports & BI Dashboard First-Load Failure
- When navigating to `Reports & BI`, `NavigationRouter.js` called `ReportsController.init()`.
- `init()` executed `await this.loadSavedFavorites()`, which invoked `this.renderCategoryPills()`.
- `renderCategoryPills` **did not exist** in `ReportsController.js`, throwing an uncaught `TypeError: this.renderCategoryPills is not a function`.
- This unhandled exception abruptly stopped execution before `init()` could populate `rep-dash-from` and `rep-dash-to` or execute `this.applyDashboardFilters()`.
- Clicking "Refresh" succeeded because `handleRefreshAction` bypassed `loadSavedFavorites` and called `this.applyDashboardFilters()` directly.

### 4. Top Shell Notification Counters Showing `0` on Initial Login
- `App.init()` polled shell counts on page boot only `if (window.AuthService.isAuthenticated())`.
- On the login screen, the user is unauthenticated, so polling was skipped.
- Upon successful authentication, `handlePostLoginSuccess` in `app.js` navigated to the landing view and preloaded modules, but **never invoked `pollShellCounts()`** or started the background polling timer.
- The shell badges remained at their default HTML placeholder value (`0`) until the user pressed F5 (browser refresh).

### 5. Saved Views Dropdown & Purple Action List in Reports Catalog
- **Saved Views Dropdown Empty**: `#viewer-saved-reports-dropdown` was only populated at line 1635 inside `loadSavedReports()`. Because `init()` crashed on line 208 (`renderCategoryPills`), `loadSavedReports()` never executed on startup. Moreover, switching to the "Saved Reports Catalog" subview never checked or refreshed the dropdown, leaving it showing only `-- Load Saved Report --`.
- **Action Buttons Desktop Parity**: In Desktop Screenshot 1 (`ReportsController.java:351-363`), the table action column features a canonical purple dropdown `::: Actions ▼` with two distinct menu actions: `👁️ Open Report` and `📅 Schedule`. Web `ReportsController.js:1667-1670` rendered separate inline buttons `<button>👁️ Open Report</button>` and `<button>⏱️ Schedule</button>`, violating desktop visual parity.

### 6. E-Way Bill Generation Error & E-Invoice (IRN) Download Failure
- **E-Way Bill 500 Server Error**: Desktop `EWayBillCenterController.java:411` submits to `POST /api/eway-bills/generate/{sale.saleId}` using the numeric primary key (`Long saleId`) of `sales_header`. Web `EWayBillController.js:240` passed `invNo` (`"JI/25-2026/0149"`) into `AccountingService.generateEWayBill(invNo)`. Because the invoice string contains slashes, the URL path was corrupted, and Spring Boot's `@PathVariable Long saleId` failed to parse it, throwing an HTTP 500/400 exception: *"Failed to generate E-Way bill: The ERP server could not complete this operation. Check the server log for the underlying error."*
- **E-Invoice IRN Download Missing**: In `EWayBillController.js:370-372`, `generateEInvoicePrompt(invNo)` called `AccountingService.generateEInvoice(invNo)` which **did not exist** in `AccountingService.js`. The call was silently skipped, a toast message was displayed, and no JSON file was exported or downloaded to the user's browser.

### 7. GST Compliance: GSTR-2B ITC Recon No Data & Return Period Dropdown
- **Return Period Textfield vs Dropdown**: Desktop `GstComplianceController.java:155-167` uses a `ComboBox<String> cmbReturnPeriod` populated with `"All Periods"` (default) and 12 monthly return periods formatted as `MM-yyyy` (`10-2026`, `09-2026`, `08-2026`, etc.). Web `index.html` had a raw textfield `<input type="text" id="gst-period-input" value="2026-10">`, requiring manual typing and lacking future month generation.
- **GSTR-2B Table Empty**: Web only queried `GET /api/gst/reconciliation/{period}` which reads the raw `gstr2b_reconciliation` database table. If government 2B JSON was not imported for that period, the backend returned an empty array `[]`. Unlike Web, Desktop (`GstComplianceController.java:506-712`) computes the authoritative ITC reconciliation, match statuses (`MATCHED` vs `GSTIN_PENDING`), and ITC eligibility directly from active ERP Purchases (`/api/purchases`), supporting both specific periods and `"All Periods"`.

### 8. Quotations Register Loading Crash (`refreshAttachmentUi` ReferenceError)
- **Top-Level Evaluation Crash**: In `QuotationController.js` line 1088, the module return block references `refreshAttachmentUi` via object shorthand (`return { ..., refreshAttachmentUi, ... }`).
- `refreshAttachmentUi` was **never defined** inside `QuotationController.js`.
- When the browser loads and evaluates `QuotationController.js`, attempting to resolve the undeclared identifier `refreshAttachmentUi` throws an immediate, fatal `ReferenceError: refreshAttachmentUi is not defined`.
- This unhandled exception abruptly terminated the execution of the entire IIFE `window.QuotationController = (function() { ... })()`, leaving `window.QuotationController` completely `undefined`.
- When navigating to the Quotations tab (`view-quotations`), `NavigationRouter.js` line 422: `if (window.QuotationController) window.QuotationController.loadQuotations();` evaluated to `false` and did nothing.
- The view remained permanently stuck in its initial static HTML state: table body displaying `Loading quotations...`, date inputs displaying empty browser placeholders `dd/mm/yyyy`, and KPI cards showing `₹ 0.00`.
- Clicking "Refresh" or "+ New Quotation" threw `TypeError: Cannot read properties of undefined (reading 'loadQuotations')`.

### 9. Reminder Center KPI Cards & Purple Action Dropdown Parity
- **Flat KPI Cards Discrepancy**: In `index.html:9815-9836`, Reminder Center used legacy `.standard-kpi-card` and `.metric-label` classes without the standard `.kpi-card` layout. They lacked glowing icon badges (`kpi-icon-badge`), semantic color accents, and standard badge styling (`pill-primary`, `pill-danger`, `pill-warning`, `pill-purple`). Because they lacked `.kpi-card` and `.kpi-label`, `KpiCardEnhancer.js` completely skipped them, leaving them rendered as dark, flat boxes mismatched from all other screens.
- **Action Column Parity Failure**: In Desktop (`ReminderCenterController.java:169-220` and `ReminderCenter.fxml`), actions are accessed via a single dropdown menu. Standard Web registers (Sales Register, Purchase Register, Quotations, Saved Views) feature a canonical purple `::: Actions ▼` dropdown button. In Web `ReminderCenterController.js:245-250`, it rendered four raw, tiny gray buttons (`✏️`, `✅`, `⏰`, `🗑️`) inside a cramped table cell without a dropdown, breaking application-wide visual consistency.

## 3. Comprehensive Implementation Plan for Build `10.0.36.04`

### Phase 1: Clock & Date Policy Centralization
1. **`js/util/FormatUtil.js`**:
   - Enhance `setBusinessPolicy(dateFormat, timeFormat, timeZone)` to:
     - Normalize and store settings in `localStorage`.
     - Update live clock instances across DOM (`#clock-display`, `#footer-live-clock`, `#auth-footer-clock`).
     - Dispatch `window.dispatchEvent(new CustomEvent('dse-date-policy-changed', { detail: { dateFormat, timeFormat, timeZone } }))`.
   - Add helper `formatClockString(date)` matching Desktop `ClockService.java:48`: `"[DayName], [formatDate] | [formatTime] | [TimezoneAbbr]"`.
2. **`js/app.js` & `js/services/BrandingService.js`**:
   - Eliminate redundant interval loops. Establish single authoritative `startClock()` in `app.js` referencing `FormatUtil.formatClockString()`.
   - Synchronize company date/time policy on login and boot before views render.

### Phase 2: Controller Date Formatting Standardization
1. Update local `formatDate` helper functions in all 8 affected controllers:
   - `AutomationCenterController.js`
   - `BankStatementController.js`
   - `CommunicationController.js`
   - `CreditDebitNoteController.js`
   - `PurchaseReconController.js`
   - `RecordPaymentController.js`
   - `ReminderCenterController.js`
   - `ReturnsController.js`
2. Connect `dse-date-policy-changed` listener in each controller to trigger table re-render when the user changes settings.

### Phase 3: Logo & Mark Startup Synchronization (Desktop Parity)
1. **`js/services/BrandingService.js`**:
   - Add `syncStartupBranding(settings)`:
     - Inspect `application.brandImagePath` / `application.banner`. If set, update `#auth-brand-banner-img.src` and ensure `#auth-brand-banner-box` is visible.
     - Inspect `application.markImagePath` / `application.mark`. If empty or null, set `#auth-brand-mark-box.style.display = 'none'` (matching Desktop lines 231–239). If present, set `#auth-brand-mark-img.src` and `#auth-brand-mark-box.style.display = 'block'`.
     - Update app header title and footers.
   - Run `syncStartupBranding()` on initial script execution from cached `localStorage` and refresh via remote settings.
2. **`js/controllers/SettingsController.js`**:
