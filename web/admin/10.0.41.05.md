## 1. Root Causes & Technical Solutions

### Issue 1: Random Mojibake Characters (`ðŸ“Š`, `âž•`, `ðŸ’¾`, etc.)
- **Root Cause:** Double-encoding corruption from Windows-1252 / UTF-8 re-saves in `commit de1dbc01` that was inherited by 23 extracted view files.
- **Solution:** Restored clean HTML entity templates (`&#128202;`, `&#9660;`, `&#10133;`, `&#8635;`, `&#128190;`, etc.) from clean baseline commit `8a136876` across all 42 views and `index.html`. All view templates now use bulletproof numeric HTML entities that cannot be corrupted by any operating system code page.

### Issue 2: Day Blinking in Footer Timestamp
- **Root Cause:** Two competing asynchronous 1000ms `setInterval` timers:
  1. `index.html:1167` (`_hydFooterClock` formatting with day name: `Thursday, 22 Oct 2026`).
  2. `FormatUtil.js:74` (`updateLiveClocks` formatting without day name: `22 Oct 2026`).
  They continuously overwrote `#footer-clock-val`, causing the day name "Thursday," to blink every second.
- **Solution:** Removed the competing recurring timer in `index.html`. Unified `FormatUtil.updateLiveClocks` as the sole authoritative clock updater with a consistent full format (`Thursday, 22 Oct 2026 | 11:40:42 PM | IST`).

### Issue 3: KPI Cards and Table Headers Mutating Before vs After Refresh
- **Root Cause:** Runtime JavaScript DOM demolition in `KpiCardEnhancer.js` and `TableUiEnhancer.js`.
  1. `KpiCardEnhancer` wiped out `card.innerHTML`, destroyed subtitles (`Total active bill value`), and injected artificial `Active` badges.
  2. `TableUiEnhancer` wiped out `<th>` elements and replaced them with colorful pill buttons.
  Depending on whether navigation was dynamic or via page refresh, the enhancer ran at different timings, causing the screen to jump from Image 2 to Image 3.
- **Solution:** 
  1. Updated `KpiCardEnhancer.js` to strictly preserve original card markup and subtitles (`kpi-sub`). Disallowed destructive `card.innerHTML` rewriting.
  2. Updated `TableUiEnhancer.js` to leave `th.innerHTML` intact, preserving clean, professional table headers matching desktop JavaFX parity.
  3. Relied on pure CSS in `app.css` for single-row proportional card layouts so that rendering is 100% identical at Frame 0 and after JavaScript loads.
